# 権利確認とセキュリティ

AI Music Video Factory バックエンドの権利確認の考え方と、セキュリティの仕組みをまとめる。実装の契約は `docs/ARCHITECTURE.md` を正とする（特に §3 設定、§5 API、§9 権利と安全）。

最終更新: 2026-10-11（基盤実装時点）

---

## 1. 認証（`AUTH_MODE`）

| モード | 用途 | 動作 |
|---|---|---|
| `dev`（既定） | ローカル開発・1 人での利用 | トークン不要。全リクエストを固定 ID の `local` ユーザーとして扱う（初回アクセス時に自動作成）。`Authorization` ヘッダーは無視する |
| `token` | 共有サーバー・複数人での利用 | `Authorization: Bearer <token>` が必須。ない・不正な場合は **401**（`WWW-Authenticate: Bearer`） |

- `token` モードのユーザーは、起動時に `API_TOKENS=name:token,name2:token2` から作成・更新する。
- DB にはトークンの **SHA-256 ハッシュだけ** を保存する。平文は保存しない。
- 同じ名前でトークンを差し替えると、同じユーザーのままトークンだけ更新する（プロジェクトは引き継ぐ）。
- 16 文字未満のトークンや書式が不正なエントリは警告ログを出す。トークン自体はログに出さない。
- `GET /api/health` と `/media/...` は認証不要。`/media` は署名がアクセス権の代わりになる（§3）。
- フロントエンドでは、ユーザーが `/settings` でトークンを入力する。トークンは localStorage に保存し、`Authorization` ヘッダーで送る。Cookie は使わない。
- **共有環境では必ず `AUTH_MODE=token` と HTTPS を使うこと。** `dev` モードはネットワークに公開しない前提である。

## 2. 所有権チェック

- プロジェクト配下のすべてのルートで `project.owner_id == current_user.id` を確認する（`security.get_owned_project` / `get_owned_clip` / `get_owned_batch` / `get_owned_video`）。
- 他人のリソースには、存在しない場合と同じ **404** を返す。ID を総当たりしても存在を確認できない。
- ダッシュボードの集計も自分のプロジェクトだけを対象にする。

## 3. 署名付きメディア URL

API のレスポンスには、ストレージのキーやファイルパスを含めない。返すのは期限付きの URL だけである。

- ローカルストレージの場合: `{PUBLIC_API_BASE_URL}/media/{key}?exp=<unix秒>&sig=<hex>[&download=1&filename=...]`
  - `sig = HMAC-SHA256(SECRET_KEY, key \n exp \n download \n filename)`。
  - `download` と `filename` も署名の対象なので、URL を書き換えてダウンロード名を偽装することはできない。
  - 署名は `hmac.compare_digest` で定数時間比較する。期限切れや改ざんがあれば **403** を返す。
  - 有効期限は `MEDIA_URL_TTL`（既定 3600 秒）。
  - HTTP Range に対応している（動画のシーク用。206 / 416）。
  - レスポンスには `X-Content-Type-Options: nosniff` を付ける。`Cache-Control: private` の max-age は残りの有効期間以内にする。
- ダウンロード時は `Content-Disposition: attachment; filename="<ASCII 代替名>"; filename*=UTF-8''<RFC 5987 エンコード>` を付ける。制御文字は除去し、ヘッダーインジェクションを防ぐ。
- S3 の場合: boto3 の presigned GET URL を返す（同じ TTL）。ダウンロード時は `ResponseContentDisposition` を付ける。バケットは **非公開** にしておくこと。
- `SECRET_KEY` が未設定だと、プロセスごとにランダムな鍵を使う（警告ログが出る）。この場合、再起動すると既存の URL は無効になる。また、API と Celery ワーカーのように複数のプロセスがあると、署名がプロセス間で一致しない。**本番では必ず設定すること。**
- 注意: 有効期限内の URL は、知っている人なら誰でも取得できる（ベアラー型の権限）。漏えいした URL を個別に失効させる仕組みはない。全 URL を失効させるには `SECRET_KEY` を変更する。

## 4. アップロードの検証

| 項目 | 内容 |
|---|---|
| 拡張子 | 許可リスト方式。音声は mp3 / wav / m4a / aac / flac / ogg、動画素材は mp4 / mov / webm / m4v |
| 中身の検査 | 拡張子だけでは判断しない。ffprobe で読み取り、(1) コンテナ形式が許可リストにあること、(2) 必要なストリーム（音声または映像）があること、を確認する。テキストファイルの拡張子を .mp3 に変えたもの、画像、音声だけのファイルなどは **400** で拒否する。MP3 のカバーアート（attached picture）は映像として扱わない |
| 長さ | 音声は 5 秒〜15 分、動画素材は 1 秒〜10 分 |
| 解像度 | 動画の長辺は 7680px 以下（デコード爆弾への対策） |
| サイズ | `MAX_AUDIO_MB` / `MAX_VIDEO_MB`。2 段階で確認する: ① ミドルウェアが `Content-Length` を見て、本文を読む前に **413** を返す。② ファイルを 1 MiB 単位でコピーしながら上限を監視し、超えた時点で中断して **413** を返す（途中まで書いたファイルは残さない） |
| 本数 | 動画素材は 1 回あたり 1〜20 本。**1 本でも不正なファイルがあれば全体を拒否する**（全か無か）。拒否した場合は何も保存しない |
| ファイル名 | 表示用の元ファイル名だけを保持する。ディレクトリ部分、制御文字、書式文字（双方向テキストの上書き文字を含む）、`<>:"/\|?*`、先頭と末尾のドット・空白は除去する。長さも制限する。日本語は残す |
| 保存パス | ユーザー入力は使わない。サーバーが `projects/{project_id}/{kind}/{asset_id}{ext}` を生成する。`LocalStorage` はキーの文字種・`..`・絶対パスを拒否し、`resolve()` した結果（シンボリックリンクも解決済み）がルート配下にあるかを確認する |
| 一時ファイル | `WORK_DIR/uploads/` に置き、成功・失敗に関係なく削除する |

エラーメッセージは日本語で `{"detail": "...", "code": "media_invalid" | "file_too_large"}` の形で返す。

## 5. API キーの扱い

- `ANTHROPIC_API_KEY`、`KLING_API_KEY`、`KLING_ACCESS_KEY`、`KLING_SECRET_KEY`、`RUNWAY_API_KEY`、`GOOGLE_API_KEY`、`S3_*` の認証情報は、**サーバー側の環境変数（`backend/.env`）でだけ** 読み込む。
- API のレスポンスに出してよいのは「設定済みかどうか」の真偽値（`configured`）だけである。キーそのものは返さない。
- `Settings` の repr にはキーを含めない（`repr=False`）。キーをログに出力してはならない。
- `backend/.env` は git の管理対象外にしている。`backend/.env.example` には空の値だけを書く。
- テスト（`tests/conftest.py`）は AI 関連のキーを空にしてから実行する。テストが有料 API を呼ぶことはない。
- ブラウザから外部の AI API を直接呼ぶことはない。生成はすべてバックエンドが仲介する。

## 6. 権利確認チェックリスト（§9）

`PUT /api/projects/{id}/rights` で次の 5 項目を記録する。5 項目すべてが true になった時点で `rights_confirmed_at` を記録する。1 項目でも false に戻すと、`rights_confirmed_at` は消える。バッチ作成（動画生成）には全項目の確認が必要である。

| キー | 確認内容 | 理由 |
|---|---|---|
| `audio_rights` | 音源の権利を保有している、または利用許諾を得ている | 原盤権・著作権を持たない音源で動画を作って配信すると、権利侵害になり、プラットフォームで削除・ミュートされる |
| `lyrics_rights` | 歌詞の権利を保有している、または利用許諾を得ている | 歌詞を画面に表示（字幕として焼き込み）することは、歌詞の複製・公衆送信にあたる。作詞者や出版社の許諾が要る |
| `no_real_person_likeness` | 実在の人物（アーティスト本人を含む）の肖像を生成しない | 肖像権・パブリシティ権の侵害やディープフェイクの問題を避けるため。多くの動画生成モデルの利用規約でも禁止されている |
| `model_terms_checked` | 使用する動画生成モデルの利用規約・商用利用条件を確認した | 商用利用の可否、クレジット表記、出力の権利帰属はプロバイダーやプランによって異なる（`docs/VIDEO_PROVIDERS.md` 参照） |
| `platform_terms` | 投稿先（Instagram 等）の規約を確認した | 音楽の利用ポリシー、AI 生成コンテンツの表示義務（AI ラベル）、ブランドコンテンツのルールに従う必要がある |

- チェックリストは **自己申告** である。システムは権利の有無を検証できない。目的は、確認を忘れたまま大量に生成してしまうことを防ぐこと、および確認した日時を記録として残すことにある。
- 未知のキーは 422 で拒否する（項目名の誤りを見逃さないため）。

## 7. 肖像（likeness）ポリシー

- 生成する人物は **架空の人物だけ** とする。実在の人物（アーティスト本人、著名人、一般人）に似せた映像は作らない。
- プロンプトを作る際の処理（`services/prompting.sanitize_prompt`）:
  - アーティスト名、「celebrity」「lookalike」「本人」など実在人物を示す表現を除去し、警告を出す。
  - すべてのプロンプトに `fictional characters only, no real or identifiable people, no celebrities` を付ける。
  - 文字の混入を防ぐため `no text, no captions, no watermark` も付ける。
- モック生成の映像には `MOCK` の表示を入れ、本物の生成結果と取り違えないようにする。
- ユーザーがアップロードする素材（実写など）に写っている人物の権利は、アップロードした人の責任とする。チェックリスト `no_real_person_likeness` は「生成しない」ことへの同意であり、アップロード素材に人物が写っているかどうかは自動では判定しない。

## 8. まだ対応していないこと

- **レート制限・不正利用対策**: API ごとのレート制限やユーザーごとの生成上限は未実装である。予算上限（`budget_limit_usd` / `DEFAULT_BUDGET_USD`）だけが費用面の歯止めになる。
- **リクエスト本文の事前制限**: マルチパートは、ハンドラーが動く前に一時ファイルへ書き出される。`Content-Length` がない chunked 送信は、事前の 413 判定をすり抜ける（ファイルごとの上限は効く）。本番ではリバースプロキシで本文サイズを制限すること（例: nginx の `client_max_body_size`）。
- **マルウェアスキャン**: アップロードファイルのウイルススキャンは行っていない（ffprobe による形式検査だけ）。
- **トークン管理**: トークンの発行・失効 API や管理画面はない。`API_TOKENS` を変更して再起動する必要がある。古いトークンでの来訪を拒否するには、そのユーザーのトークンを差し替えること。
- **署名 URL の個別失効**: できない（§3）。
- **監査ログ**: 誰がいつ何を生成・削除したかの監査ログはない。
- **生成物の自動審査**: 生成された動画に実在人物、ロゴ、不適切な内容が含まれていないかの自動判定はしていない。公開前に人が確認すること。
- **権利の実際の検証**: 音源・歌詞の権利情報（ISRC や JASRAC 等の管理状況）との照合はしていない。
- **保存データの暗号化**: ストレージや DB の暗号化はインフラ側に依存する。アプリケーション層では暗号化していない。
- **TLS 終端・セキュリティヘッダー**: HTTPS 化、HSTS、CSP はリバースプロキシやフロントエンド側で設定する前提である。
- **DB マイグレーション**: Alembic は未導入（`create_all` のみ）。スキーマを変更する際は手動対応が必要になる。
- **依存パッケージの脆弱性スキャン**: 未実施。
