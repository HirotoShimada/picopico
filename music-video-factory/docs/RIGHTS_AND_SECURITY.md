# 権利確認とセキュリティ

AI Music Video Factory バックエンドの権利確認の考え方と、セキュリティの仕組みをまとめる。実装の契約は `docs/ARCHITECTURE.md` を正とする（特に §3 設定、§5 API、§9 権利と安全）。

最終更新: 2026-10-11（2 回目のレビュー指摘の修正後）

---

## 1. 認証（`AUTH_MODE`）

| モード | 用途 | 動作 |
|---|---|---|
| `dev`（既定） | ローカル開発・1 人での利用 | トークン不要。全リクエストを固定 ID の `local` ユーザーとして扱う（初回アクセス時に自動作成）。`Authorization` ヘッダーは無視する |
| `token` | 共有サーバー・複数人での利用 | `Authorization: Bearer <token>` が必須。ない・不正な場合は **401**（`WWW-Authenticate: Bearer`） |

- `token` モードのユーザーは、起動時に `API_TOKENS=name:token,name2:token2` から作成・更新する。
- DB にはトークンの **SHA-256 ハッシュだけ** を保存する。平文は保存しない。
- 同じ名前でトークンを差し替えると、同じユーザーのままトークンだけ更新する（プロジェクトは引き継ぐ）。
- `API_TOKENS` から外したユーザーは、次の起動時にトークンが無効になる（DB のハッシュを消す。ログに名前を出す）。
  プロジェクトは残り、同じ名前で再び追加すると同じユーザーとして使える。
- 16 文字未満のトークンや書式が不正なエントリは警告ログを出す。トークン自体はログに出さない。
- `GET /api/health`、`/media/...`、`/media-zip/...` は認証不要。署名がアクセス権の代わりになる（§3）。
- フロントエンドでは、ユーザーが `/settings` でトークンを入力する。トークンは localStorage に保存し、`Authorization` ヘッダーで送る。Cookie は使わない。
- **共有環境では必ず `AUTH_MODE=token` と HTTPS を使うこと。** `dev` モードはネットワークに公開しない前提である。

## 2. 所有権チェック

- プロジェクト配下のすべてのルートで `project.owner_id == current_user.id` を確認する（`security.get_owned_project` / `get_owned_clip` / `get_owned_batch` / `get_owned_video`）。
- 他人のリソースには、存在しない場合と同じ **404** を返す。ID を総当たりしても存在を確認できない。
- ダッシュボードの集計も自分のデータだけを対象にする。利用額は費用記録の所有者（`CostRecord.owner_id`。記録の作成時に
  プロジェクトの所有者を入れる）で集計するので、削除したプロジェクトの費用も含まれる（§8 の「費用記録の保持」）。

## 3. 署名付きメディア URL

API のレスポンスには、ストレージのキーやファイルパスを含めない。返すのは期限付きの URL だけである。

- ローカルストレージの場合: `{PUBLIC_API_BASE_URL}/media/{key}?exp=<unix秒>&sig=<hex>[&download=1&filename=...]`
  - `sig = HMAC-SHA256(SECRET_KEY, key \n exp \n download \n filename)`。
  - `download` と `filename` も署名の対象なので、URL を書き換えてダウンロード名を偽装することはできない。
  - 署名は `hmac.compare_digest` で定数時間比較する。期限切れや改ざんがあれば **403** を返す。
  - 有効期限は `MEDIA_URL_TTL`（既定 3600 秒）。
  - HTTP Range に対応している（動画のシーク用。206 / 416）。
  - レスポンスには `X-Content-Type-Options: nosniff` を付ける。`Cache-Control: private` の max-age は残りの有効期間以内にする。
- ダウンロード時は `Content-Disposition: attachment; filename="<ASCII 代替名>"; filename*=UTF-8''<RFC 5987 エンコード>` を付ける。制御文字は除去し、ヘッダーインジェクションを防ぐ。
- S3 の場合: boto3 の presigned GET URL を返す（同じ TTL）。ダウンロード時は `ResponseContentDisposition` を付ける。バケットは **非公開** にしておくこと。
- `SECRET_KEY` が未設定だと、プロセスごとにランダムな鍵を使う（警告ログが出る）。この場合、再起動すると既存の URL は無効になる。また、API と Celery ワーカーのように複数のプロセスがあると、署名がプロセス間で一致しない。**本番では必ず設定すること。**
- 注意: 有効期限内の URL は、知っている人なら誰でも取得できる（ベアラー型の権限）。漏えいした URL を個別に失効させる仕組みはない。全 URL を失効させるには `SECRET_KEY` を変更する。

### 署名付き ZIP リンク

ZIP（ジョブの完成分・選択した動画）は、ブラウザが通常のダウンロードとして保存できるよう、署名付きリンクで配る。
トークン認証でも、ページのメモリに読み込まずにストリーミングで保存できる。

- `POST /api/batches/{id}/zip-link`、`POST /api/videos/zip-link {video_ids}` は通常の認証と所有権チェック（他人の ID は 404）を
  通ったうえで、完成済みの動画の ID だけを署名した `{url, expires_at}` を返す（完成済みがなければ 409 `no_videos`）。
- URL は `{PUBLIC_API_BASE_URL}/media-zip/{ファイル名}?owner=<ユーザー ID>&videos=<ID 列>&exp=<unix秒>&sig=<hex>`。
  `videos` は動画 ID（16 バイト）を連結した base64url。
  `sig = HMAC-SHA256(SECRET_KEY, "zip-link" \n owner \n ソートした動画 ID \n exp \n ファイル名)`。用途を表す
  `zip-link` を含めるので、`/media` の署名と取り違えられない。ID・所有者・期限・ファイル名のどれを書き換えても **403**。
  有効期限は `MEDIA_URL_TTL`（既定 3600 秒）。
- 配信時に、動画をその所有者のプロジェクトに属するものとして読み直す。リンクの発行後に削除された動画や、所有者が
  変わった動画は ZIP に入れない。残りがなければ 409 `no_videos`。
- レスポンスには `Cache-Control: private, no-store` と `X-Content-Type-Options: nosniff` を付ける。
- URL には内部のユーザー ID と動画 ID が入る（秘密ではないが、URL を共有すると見える）。`/media` と同じくベアラー型の
  権限で、期限内なら URL を知っている人は誰でも取得でき、個別には失効できない。

## 4. アップロードの検証

| 項目 | 内容 |
|---|---|
| 拡張子 | 許可リスト方式。音声は mp3 / wav / m4a / aac / flac / ogg、動画素材は mp4 / mov / webm / m4v |
| 中身の検査 | 拡張子だけでは判断しない。ffprobe で読み取り、(1) コンテナ形式が許可リストにあること（楽曲では Matroska / WebM は不可）、(2) 必要なストリーム（音声または映像）があること、を確認する。テキストファイルの拡張子を .mp3 に変えたもの、画像、音声だけのファイルなどは **400** で拒否する。MP3 のカバーアート（attached picture）は映像として扱わない |
| 長さ | 音声は 5 秒〜15 分、動画素材は 1 秒〜10 分。音声の長さはヘッダーの値ではなく **実際にデコードした長さ**（8 kHz モノラルに変換して数え、上限を超えた時点で打ち切る）で判定する。ヘッダーの長さを偽装したファイル（例: 前半だけ高ビットレートの ADTS）で上限をすり抜けることはできない。解析側でも 15 分 + 1 秒を超えてはデコードしない |
| 解像度 | 動画の長辺は 7680px 以下（デコード爆弾への対策） |
| サイズ | `MAX_AUDIO_MB` / `MAX_VIDEO_MB`。2 段階で確認する: ① ミドルウェアが `Content-Length` を見て、本文を読む前に **413** を返す。② ファイルを 1 MiB 単位でコピーしながら上限を監視し、超えた時点で中断して **413** を返す（途中まで書いたファイルは残さない） |
| 本数 | 動画素材は 1 回あたり 1〜20 本。**1 本でも不正なファイルがあれば全体を拒否する**（全か無か）。拒否した場合は何も保存しない |
| ファイル名 | 表示用の元ファイル名だけを保持する。ディレクトリ部分、制御文字、書式文字（双方向テキストの上書き文字を含む）、`<>:"/\|?*`、先頭と末尾のドット・空白は除去する。長さも制限する。日本語は残す |
| 保存パス | ユーザー入力は使わない。サーバーが `projects/{project_id}/{kind}/{asset_id}{ext}` を生成する。`LocalStorage` はキーの文字種・`..`・絶対パスを拒否し、`resolve()` した結果（シンボリックリンクも解決済み）がルート配下にあるかを確認する |
| 一時ファイル | `WORK_DIR/uploads/` に置き、成功・失敗に関係なく削除する |

エラーメッセージは日本語で `{"detail": "...", "code": "media_invalid" | "file_too_large"}` の形で返す。

## 5. API キーの扱い

- `ANTHROPIC_API_KEY`、`KLING_API_KEY`、`KLING_ACCESS_KEY`、`KLING_SECRET_KEY`、`RUNWAY_API_KEY`、`GOOGLE_API_KEY`、`S3_*` の認証情報は、**サーバー側の環境変数（`backend/.env`）でだけ** 読み込む。
- API のレスポンスに出してよいのは「設定済みかどうか」の真偽値（`configured`）だけである。キーそのものは返さない。
- `Settings` の repr にはキーを含めない（`repr=False`）。キーをログに出力してはならない。
- `backend/.env` は git の管理対象外にしている。`backend/.env.example` には空の値だけを書く。
- テスト（`tests/conftest.py`）は AI 関連のキーを空にしてから実行する。テストが有料 API を呼ぶことはない。
- ブラウザから外部の AI API を直接呼ぶことはない。生成はすべてバックエンドが仲介する。

### 外部 API に送るデータ

| 送信先 | 送る内容 | 送らないもの |
|---|---|---|
| 動画生成 API（Veo / Runway / Kling） | 英語のプロンプト（世界観・シーン・カメラ・色の説明、ネガティブプロンプト）、長さ・アスペクト比・シード、画像→動画のときは入力画像 | 楽曲、歌詞の本文、楽曲名、アーティスト名 |
| Anthropic（Claude。`ANTHROPIC_API_KEY` を設定した場合のみ） | 楽曲名・ムード・目的・カスタム世界観・**歌詞の本文**・楽曲解析の要約（BPM、セクションとエネルギー、音源のムード）・感情と世界観の推定 | 楽曲の音声。アーティスト名と別表記は「描写してはいけない名前」としてのみ送り、他の項目からは取り除く |

- Claude は絵コンテ生成（バッチの計画、絵コンテのプレビュー）でのみ呼ぶ。バッチでは、同じ世界観・楽曲・歌詞の前回の
  Claude の絵コンテを再利用して再び送信しない（「絵コンテを Claude で新しく作り直す」を選んだ場合を除く）。
  プレビューは押すたびに送信する。
- 歌詞を外部に送りたくない場合は `ANTHROPIC_API_KEY` を設定しないこと（テンプレートで絵コンテを作る）。
- バッチは権利確認の全項目がそろうまで作れない（§6）。絵コンテのプレビュー（`POST /api/projects/{id}/storyboard`）は、
  プロジェクトに歌詞の行があり「歌詞の権利」（`lyrics_rights`）が未確認のあいだ Claude を呼ばず、歌詞を送らずに
  テンプレートで作る（警告を先頭に付ける。費用は記録しない）。プレビューは予算を確認しない。
- Claude によるプレビューは、ユーザーごとに **10 分間で 10 回まで**（`CLAUDE_PREVIEW_LIMIT` / `CLAUDE_PREVIEW_WINDOW_SEC`）。
  超えると **429**（`code: "rate_limited"`、待ち時間を含む日本語のメッセージ、`Retry-After` ヘッダー。CORS でブラウザから
  読める）を返す。テンプレートのプレビューは数えない。1 回あたりの費用は `max_tokens` で上限がある（Opus 5.5 で最大約
  $0.32）ので、プレビューの費用はユーザーごとに 10 分あたり最大約 $3.2 になる。回数は API プロセスのメモリで数える
  （再起動で数え直し、複数プロセスではプロセスごと。§8）。

## 6. 権利確認チェックリスト（§9）

`PUT /api/projects/{id}/rights` で次の 5 項目を記録する。5 項目すべてが true になった時点で `rights_confirmed_at` を記録する。1 項目でも false に戻すと、`rights_confirmed_at` は消える。

全項目の確認が必要な操作: バッチ作成、動画の再生成・編集（再レンダリング）・再試行（いずれも 422 `rights_unconfirmed`）。
実行待ちの処理もタスクの中で確認し直すため、確認を取り消すと、まだ始まっていない素材生成・レンダリングは止まる
（素材は生成を送信せずに失敗、動画は失敗、計画中のバッチは失敗）。

| キー | 確認内容 | 理由 |
|---|---|---|
| `audio_rights` | 音源の権利を保有している、または利用許諾を得ている | 原盤権・著作権を持たない音源で動画を作って配信すると、権利侵害になり、プラットフォームで削除・ミュートされる |
| `lyrics_rights` | 歌詞の権利を保有している、または利用許諾を得ている | 歌詞を画面に表示（字幕として焼き込み）することは、歌詞の複製・公衆送信にあたる。作詞者や出版社の許諾が要る |
| `no_real_person_likeness` | 実在の人物（アーティスト本人を含む）の肖像を生成しない | 肖像権・パブリシティ権の侵害やディープフェイクの問題を避けるため。多くの動画生成モデルの利用規約でも禁止されている |
| `model_terms_checked` | 使用する動画生成モデルの利用規約・商用利用条件を確認した | 商用利用の可否、クレジット表記、出力の権利帰属はプロバイダーやプランによって異なる（`docs/VIDEO_PROVIDERS.md` 参照） |
| `platform_terms` | 投稿先（Instagram 等）の規約を確認した | 音楽の利用ポリシー、AI 生成コンテンツの表示義務（AI ラベル）、ブランドコンテンツのルールに従う必要がある |

- チェックリストは **自己申告** である。システムは権利の有無を検証できない。目的は、確認を忘れたまま大量に生成してしまうことを防ぐこと、および確認した日時を記録として残すことにある。
- 未知のキーは 422 で拒否する（項目名の誤りを見逃さないため）。
- **内容が変わると確認を取り消す**（`pipeline.revoke_right`）。確認は、確認した時点の音源・歌詞に対するものだからである。
  - 音源のアップロード（差し替え・初回とも）: 「音源の権利」が確認済みなら未確認に戻し、`rights_confirmed_at` を消す。
    応答（`ProjectOut.warnings`）にその旨の日本語の警告を入れる。
  - 歌詞の本文の変更（`PUT /lyrics`、歌詞ファイルのアップロード、`PUT /lyrics/lines` での表記の編集）: 歌われる行の文字が
    変わったときだけ「歌詞の権利」を未確認に戻し、警告を返す（`LyricsParseOut.warnings` / `LyricLinesOut.warnings`）。
    タイミングだけの変更、同じ歌詞の保存し直し、見出し行（`[サビ]` など。歌詞の行に含めない）の有無は変更に数えない。
  - 未確認に戻ると、バッチ作成・再生成・編集・再試行は 422 `rights_unconfirmed` になり、実行待ちの処理もタスク内の確認で止まる。
  - 画面は、変更した場所（楽曲ファイルのカード・歌詞タブ）と権利確認タブ・プロジェクトの見出しに「要再確認」を表示する。
    どの項目が戻ったかは API が変更時の応答でしか返さないため、ブラウザの localStorage（`mvf.rightsReset`）に記録する。
    ほかのブラウザでは通常の「未確認」として表示される。

## 7. 肖像（likeness）ポリシー

- 生成する人物は **架空の人物だけ** とする。実在の人物（アーティスト本人、著名人、一般人）に似せた映像は作らない。
- すべてのプロンプトは `services/prompting.sanitize_prompt` を通る。次のものを除去し、日本語の警告を出す:
  - アーティスト名、プロジェクトに登録した **別表記**（`artist_aliases`。ローマ字・英語表記など）、かな表記のアーティスト名の
    ローマ字（例: あいみょん → aimyon）。表記ゆれ（大文字小文字・全角半角・空白・ハイフン）を無視して照合する。
  - 「本人」「芸能人」「有名人」「そっくり」「激似」「モノマネ」「〜似の」「〜に似た」「風の顔」「みたいな顔」などの日本語表現と、
    その前に書かれた名前。
  - 英語の look-alike 表現と、それが指す人物: `<Name> lookalike / vibes / -esque / style`、`looks (exactly) like <person>`、
    `resembling` / `resemblance to` / `likeness of` / `spitting image of`、`in the style of / inspired by / vibes of / like <Name>`。
    ただし対象が一般的な語彙なら残す（例: "looks like a dream"）。
  - 語彙にない大文字始まりの語が 2 語以上続くもの（人名の可能性が高い。例: Taylor Swift、Keanu Reeves）。
  - Claude を使う場合、Claude が出力の中で見つけた実在の人物（`detected_real_people`）。
- カスタム世界観・ムード・目的に書かれた人名も「描写してはいけない名前」に加える。英字のムードは、許可した気分の語だけを
  プロンプトに使い、そのままコピーしない。
- すべてのプロンプトに `fictional characters only, no real or identifiable people, no celebrities` を付ける。
  文字の混入を防ぐため `no text, no captions, no watermark` も付ける。Runway の Gen-4 系モデルには公人の検出を既定の強さ（`publicFigureThreshold: auto`）で依頼し、緩めない。
- **限界**: 語句ベースの検出である。look-alike 表現を伴わない 1 語だけの人名や、漢字のアーティスト名のローマ字表記は、
  別表記に登録するか Claude を使わないと除去されない。逆に、辞書にない 2 語の地名（例: Times Square）が人名として除去される
  ことがある（警告が出る）。生成された映像に実在の人物が写っていないかの自動判定はしていないので、公開前に人が確認すること。
- モック生成の映像には `MOCK` の表示を入れ、本物の生成結果と取り違えないようにする。
- ユーザーがアップロードする素材（実写など）に写っている人物の権利は、アップロードした人の責任とする。チェックリスト `no_real_person_likeness` は「生成しない」ことへの同意であり、アップロード素材に人物が写っているかどうかは自動では判定しない。
  左右反転は素材内の文字やロゴを鏡文字にするため、既定では使わない。生成設定の「左右反転を使う」（`allow_mirror`）を
  オンにしたときだけ、動画ごとのバリエーションとして一部のショットを反転する。

## 8. まだ対応していないこと

- **レート制限・不正利用対策**: レート制限は Claude による絵コンテのプレビュー（ユーザーごとに 10 分間で 10 回、§5）だけで、
  API 全体のレート制限やユーザーごとの生成上限は未実装である。プレビューの回数は API プロセスのメモリで数えるため、
  再起動で数え直し、複数の API プロセスではプロセスごとに数える（共有するには Redis などで数える必要がある）。
  素材生成の費用面の歯止めは予算上限（`budget_limit_usd` / `DEFAULT_BUDGET_USD`）だけである。予算は素材生成の試行ごとに DB で原子的に予約するため、並行する処理があっても上限を超えて発注しない。ただし、Veo / Kling のようにキャンセル API がないプロバイダーで中断したジョブは、課金されたものとして記録する（推定）。絵コンテのプレビュー（Claude）は予算の対象外である。
- **リクエスト本文の事前制限**: マルチパートは、ハンドラーが動く前に一時ファイルへ書き出される。`Content-Length` がない chunked 送信は、事前の 413 判定をすり抜ける（ファイルごとの上限は効く）。本番ではリバースプロキシで本文サイズを制限すること（例: nginx の `client_max_body_size`）。
- **マルウェアスキャン**: アップロードファイルのウイルススキャンは行っていない（ffprobe による形式検査だけ）。
- **トークン管理**: トークンの発行・失効 API や管理画面はない。`API_TOKENS` を変更して再起動する必要がある（外したユーザー・差し替えた古いトークンは起動時に無効になる）。
- **署名 URL の個別失効**: できない（`/media`・`/media-zip` とも。§3）。
- **監査ログ**: 誰がいつ何を生成・削除したかの監査ログはない。
- **生成物の自動審査**: 生成された動画に実在人物、ロゴ、不適切な内容が含まれていないかの自動判定はしていない。公開前に人が確認すること。
- **権利の実際の検証**: 音源・歌詞の権利情報（ISRC や JASRAC 等の管理状況）との照合はしていない。内容の変更で確認を取り消すが（§6）、
  確認そのものは自己申告である。どの項目が取り消されたかは、変更したブラウザにしか記録しない。
- **費用記録の保持**: プロジェクトを削除しても費用記録（`CostRecord`）は残る（`project_id` を NULL にし、`owner_id` で利用者に
  ひも付けたまま）。ダッシュボードの利用額は減らない。既存のデータベースは API の起動時に自動で移行する（`db.init_db`）。
  ユーザー（`User`）を DB から直接削除した場合は、その費用記録も削除される（`owner_id` は `ON DELETE CASCADE`）。
- **保存データの暗号化**: ストレージや DB の暗号化はインフラ側に依存する。アプリケーション層では暗号化していない。
- **TLS 終端・セキュリティヘッダー**: HTTPS 化、HSTS、CSP はリバースプロキシやフロントエンド側で設定する前提である。
- **DB マイグレーション**: Alembic は未導入（`create_all` のみ）。起動時の自動更新は、足りない NULL 可の列（外部キー付きを含む）の追加（`db.add_missing_columns`）、`cost_records.project_id` の NULL 可・`ON DELETE SET NULL` への変更（`db.relax_foreign_keys`）、`cost_records.owner_id` の補完（`db.backfill_columns`）だけで、それ以外のスキーマ変更は手動対応が必要になる。
- **依存パッケージの脆弱性スキャン**: 未実施。
