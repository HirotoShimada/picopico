## 4. Data model (`app/models.py`, SQLAlchemy 2.0 typed ORM)

Use portable types only: `String`, `Text`, `Integer`, `Float`, `Boolean`, `DateTime(timezone=True)`, `JSON` (works on Postgres and SQLite). IDs are `String(32)` = `uuid4().hex`. All tables have `created_at`; mutable ones `updated_at`.

- **User**: `id`, `name`, `token_hash` (sha256 hex, nullable), `created_at`.
- **Project**: `id`, `owner_id`→User, `title` (楽曲名), `artist_name`, `artist_aliases` JSON list (other spellings, e.g. romanised; nullable, added later), `mood` (雰囲気, free text), `purpose` (動画生成目的), `notes`,
  `audio_asset_id`→Asset (nullable), `analysis` JSON (AudioAnalysis §6.1, nullable), `analysis_status` (`none|queued|running|done|failed`), `analysis_error`,
  `lyrics_text` Text, `lyrics_format` (`txt|lrc|srt`), `lyric_lines` JSON (list of LyricLine §6.2, default `[]`),
  `segment_start` Float, `segment_end` Float (user-selected/confirmed section, nullable),
  `world_preset` (default `cinematic`), `custom_world` Text,
  `rights` JSON (dict key→bool, §9), `rights_confirmed_at`,
  `budget_limit_usd` Float nullable, `created_at`, `updated_at`.
- **Asset**: `id`, `project_id`, `owner_id`, `kind` (`audio|lyrics|material|clip|render|thumbnail|zip`), `filename` (original, sanitized), `storage_key`, `content_type`, `size_bytes`, `duration` Float, `width`, `height`, `meta` JSON, `created_at`.
- **Clip** (video material pool, uploaded or generated): `id`, `project_id`, `source` (`upload|mock|kling|runway|veo|openrouter`), `provider`, `model`, `scene_id` (storyboard scene id, nullable), `prompt` Text, `negative_prompt` Text, `params` JSON, `cache_key` (String(64), indexed), `status` (`pending|generating|ready|failed|cancelled`), `asset_id`→Asset nullable, `thumbnail_asset_id`, `duration`, `width`, `height`, `cost_usd` Float default 0, `external_job_id`, `error`, `attempts` Int, `created_at`, `updated_at`.
- **Batch** (one generation run): `id`, `project_id`, `settings` JSON (GenerationSettings §5), `estimate` JSON (Estimate §6.5), `storyboard` JSON (§6.3), `plan` JSON (BatchPlan summary §6.4), `status` (`queued|planning|generating_clips|rendering|completed|partial|failed|cancelled|budget_exceeded`), `error`, `cost_usd` Float, `created_at`, `started_at`, `finished_at`.
- **Video** (one output MP4): `id`, `project_id`, `batch_id`, `index` Int, `title`, `status` (`queued|waiting_clips|rendering|done|failed|cancelled`), `progress` Float 0..1, `plan` JSON (VideoPlan §6.4), `asset_id`, `thumbnail_asset_id`, `quality` JSON (QualityReport §6.6), `favorite` Bool, `error`, `attempts`, `render_version` Int (increments on re-render), `created_at`, `updated_at`, `rendered_at`.
- **CostRecord**: `id`, `project_id` (nullable, FK `ON DELETE SET NULL`), `owner_id`→User (nullable, indexed; review fix), `batch_id` nullable, `clip_id` nullable, `kind` (`video_generation|llm`), `provider`, `model`, `units` Float, `unit` (`second|token|clip`), `unit_price_usd`, `amount_usd`, `cached` Bool (true when a cache hit avoided spend; amount 0), `note`, `created_at`.
  As implemented (review fix): cost records **outlive their project** — `Project.cost_records` has no delete cascade and the database sets `project_id` to NULL, so deleting a project never lowers the usage totals. `owner_id` is filled from the project's owner by a `before_insert` mapper event (`models._fill_cost_record_owner`), whichever code path creates the record; the dashboard aggregates by `owner_id`.

`init_db()` calls `Base.metadata.create_all()` (MVP; no Alembic yet) and then upgrades an existing database in place; every step is idempotent (on an up-to-date schema it only inspects):
1. `relax_foreign_keys()`: the columns in `db.RELAXED_FOREIGN_KEYS` (`cost_records.project_id`, created `NOT NULL … ON DELETE CASCADE` by older versions) are made nullable with the model's `ON DELETE` action — PostgreSQL: `DROP NOT NULL` + the FK constraint dropped and re-created in one transaction; SQLite: the table is rebuilt (renamed, re-created from the model, rows copied, old table dropped) inside an explicit `BEGIN`, with references to missing rows set to NULL.
2. `add_missing_columns()`: nullable model columns that an existing table lacks are added with `ALTER TABLE … ADD COLUMN` (e.g. `projects.artist_aliases`), including a single-column foreign key's `REFERENCES … ON DELETE …` clause and the column's index (e.g. `cost_records.owner_id`); other missing columns are only logged.
3. `backfill_columns()`: `cost_records.owner_id` is filled from the project's owner where it is still NULL.

## 5. HTTP API (all JSON under `/api`, except multipart uploads and media)

Errors: FastAPI default `{"detail": "..."}` with proper status codes (400 validation of files, 404 not found / not owned, 409 state conflict, 413 too large, 422 schema, 402-style budget refusal → use 422 with detail code). Every project-scoped route checks `project.owner_id == current_user.id` (404 otherwise).

Timestamps ISO-8601. Media URLs in responses are **signed absolute URLs** (`{PUBLIC_API_BASE_URL}/media/{key}?exp=..&sig=..`) — never raw storage keys.

### 5.1 System & dashboard
- `GET /api/health` → `{status:"ok"|"degraded", db:bool, redis:bool, ffmpeg:bool, task_mode, storage_backend}` (no auth; never raises; `degraded` when db or ffmpeg — or redis in `celery` mode — is down)
- `GET /api/system/capabilities` → `{providers:[ProviderInfo], claude_configured:bool, whisper:{available:bool, reason?:string}, presets:[WorldPresetInfo], lyric_styles:[{id,name_ja,description}], color_grades:[{id,name}], fonts:[{id,family,label}], durations:[15,30,60], counts:[1,3,5,10,30], limits:{max_audio_mb,max_video_mb,max_count:50,min_duration:5,max_duration:90}, generation_options:[{id,name_ja,description_ja,default}]}` — `generation_options` (extension) lists the boolean `GenerationSettings` options; today only `allow_mirror` (default `false`).
  - `ProviderInfo = {id, name, configured:bool, available:bool, reason?:string, kind:"mock"|"library"|"api", commercial_use_note, models:[{id,name,clip_durations:[number], max_clip_duration, resolution, supports_vertical:bool, price_per_second_usd:number, price_note, verified:bool}]}`
  - As implemented (OpenRouter, extensions): model entries add `price_known: bool`; `price_per_second_usd` is `null` when `price_known` is false (an OpenRouter listing entry without a readable price — such a model cannot be selected). The `openrouter` provider entry adds `models_source: "live"|"cache"|"fallback"`, `models_fetched_at` (ISO or null) and `models_note` (ja). `claude_configured` is true for either Claude route, and `llm = {route: "anthropic"|"openrouter"|null, model, data_policy_note (ja: what is sent where), verified: false}` says which (`llm.llm_info()`; no secrets).
- `GET /api/dashboard` → `{projects:int, videos_done:int, videos_total:int, active_jobs:[{batch_id, project_id, project_title, status, done, total, failed}], recent_videos:[VideoOut], usage:{total_usd, month_usd, by_provider:[{provider, amount_usd, clips}], clips_generated:int, clips_reused:int, saved_usd:number}, pending_estimate_usd:number}` — `usage` covers all of the user's `CostRecord`s (`owner_id`), including those of deleted projects.

### 5.2 Projects
- `GET /api/projects` → `[ProjectSummary]` (`id,title,artist_name,created_at,updated_at,has_audio,analysis_status,lyric_line_count,video_count,cover_url?`)
- `POST /api/projects` `{title, artist_name, artist_aliases?: [string ≤100] (≤10, cleaned + de-duplicated), mood?, purpose?, notes?, world_preset?, custom_world?, budget_limit_usd?}` → `ProjectOut` (includes `artist_aliases`, `[]` by default; `PATCH` rejects `null`)
- `GET /api/projects/{id}` → `ProjectOut` = all Project fields (minus owner) + `audio: AssetOut|null` + `counts:{clips,videos,batches}` (all rows, cancelled ones included) + `warnings:[string]` (extension: notices about this request only, e.g. `POST /audio` un-confirming `audio_rights`; `[]` otherwise)
- `PATCH /api/projects/{id}` partial update of editable fields → `ProjectOut`
- `DELETE /api/projects/{id}` → 204 (deletes stored files too; its `CostRecord`s are kept with `project_id = NULL`, §4)
- `PUT /api/projects/{id}/rights` `{items:{key:bool}}` → `ProjectOut` (sets `rights_confirmed_at` when all required items true)
- `AssetOut = {id, kind, filename, content_type, size_bytes, duration, width, height, url, created_at}`

### 5.3 Audio & analysis
- `POST /api/projects/{id}/audio` multipart `file` → validates (extension in mp3,wav,m4a,aac,flac,ogg; ffprobe must find an audio stream in an allowed container — Matroska/WebM are not accepted for songs; size ≤ MAX_AUDIO_MB; duration 5 s–15 min measured on the **decoded** audio (`media.decoded_audio_duration`, 8 kHz mono, stops past the limit), so a header that under-reports the length cannot pass) → stores Asset(kind=audio), sets `analysis_status=queued`, enqueues analysis → `ProjectOut` (201). A confirmed `audio_rights` item is un-confirmed (and `rights_confirmed_at` cleared) by every song upload, first or replacement, since the confirmation vouched for another file; `warnings` then carries `pipeline.AUDIO_RIGHTS_RESET_MESSAGE`
- `GET /api/projects/{id}/analysis` → `{status, error?, analysis: AudioAnalysis|null, segment:{start,end}|null}`
- `POST /api/projects/{id}/analysis/rerun` → 202 `{status}`
- `PUT /api/projects/{id}/segment` `{start, end}` (validated within duration, end-start ≥ 3) → `{segment}`
- `GET /api/projects/{id}/world-estimate` (extension, 感情・世界観推定) → `{emotions:[id], themes:[id], mood_en, recommended_presets:[preset id], sources:{audio,lyrics,user:[id]}, rationale_ja, analysis_used:bool}` = `storyboard.estimate_world(analysis if done else None, lyric_lines, mood, purpose)`; deterministic, no API call. Emotion ids `melancholic nostalgic hopeful energetic romantic calm dark dreamy`, themes `night nature`.

### 5.4 Lyrics
- `PUT /api/projects/{id}/lyrics` `{text, format?: "auto"|"txt"|"lrc"|"srt"}` → `{format, lines:[LyricLine], warnings:[string]}` (text stored verbatim; never rewritten)
- `POST /api/projects/{id}/lyrics/upload` multipart `file` (.txt/.lrc/.srt, ≤1 MB, UTF-8 or UTF-8-BOM or Shift_JIS) → same response
- `GET /api/projects/{id}/lyrics` → `{text, format, lines}`
- `PUT /api/projects/{id}/lyrics/lines` `{lines:[LyricLine]}` (manual timing edits; text of a line may be edited only by the user) → `{lines, warnings:[string]}` (`warnings` extension, see §5.9)
- `POST /api/projects/{id}/lyrics/auto-time` `{method:"heuristic"|"whisper", start?, end?, overwrite_timed?:bool}` → `{lines, method_used, warnings}`; whisper unavailable → 503 `{detail}`
- `GET /api/projects/{id}/lyrics/export?format=lrc|srt` → text/plain attachment

### 5.5 Clips (video materials)
- `GET /api/projects/{id}/clips?include_cancelled=true|false` → `[ClipOut]` (`id, source, provider, model, scene_id, prompt, status, duration, width, height, cost_usd, error, url?, thumbnail_url?, created_at, used_in_videos:int`). `include_cancelled` (extension, default `true`): `false` leaves out `cancelled` clips. `used_in_videos` counts the project's videos whose plan uses the clip, **not counting cancelled videos**.
- `POST /api/projects/{id}/clips/upload` multipart `files` (1..20; mp4,mov,webm,m4v; video stream required; ≤ MAX_VIDEO_MB; 1 s–10 min) → `[ClipOut]` (source=`upload`, status=`ready`, thumbnail generated)
- `DELETE /api/clips/{clip_id}` → 204 (409 if used by a video currently rendering)

### 5.6 Storyboard, estimate, batches
- `POST /api/projects/{id}/storyboard` `{preset, custom_world?, scenes?:int}` → `Storyboard` (§6.3) (does not persist; preview)
- `POST /api/projects/{id}/estimate` `GenerationSettings` → `Estimate` (§6.5)
- `POST /api/projects/{id}/batches` `GenerationSettings` → `BatchOut` (201). Rejects 422 when: no audio/analysis, rights not confirmed, provider not configured, estimate > budget, `library` provider with no ready uploaded clips.
- `GET /api/projects/{id}/batches` → `[BatchOut]`
- `GET /api/batches/{id}` → `BatchOut` with `videos:[VideoOut]`, `clips:[ClipOut]`
- `POST /api/batches/{id}/cancel` → `BatchOut`
- `GET /api/batches/{id}/zip` → `application/zip` stream of all `done` videos (also `POST /api/videos/zip {video_ids}` for a selection)
- `POST /api/batches/{id}/zip-link` and `POST /api/videos/zip-link {video_ids}` (extension) → `ZipLinkOut {url, expires_at}`: a signed `GET /media-zip/…` link (§5.8) to the same archive that a browser downloads by itself, also in token mode (no auth header needed). 409 `no_videos` when none of the videos is done; every id must be owned (404 otherwise).

`GenerationSettings`:
```json
{
  "preset": "cinematic|emotional|urban_night|nostalgic|nature|dark|dreamy|documentary|custom",
  "custom_world": "string|null",
  "provider": "mock|library|kling|runway|veo|openrouter",
  "model": "string|null",            // provider default when null
  "duration_sec": 15,                // 5..90
  "count": 3,                        // 1..50
  "lyric_style": "auto|simple|cinematic|minimal|karaoke|fade",   // auto = the preset's styles rotated per video
  "text_style": TextStyle,           // optional overrides, see 6.6
  "color_grade": "auto|<grade id>",  // auto = varied per video from preset
  "start_strategy": "segment|chorus|varied|custom",
  "start_sec": null,                 // used when custom
  "reuse": "max_variety|balanced|economy",
  "max_new_clips": null,             // hard cap on newly generated clips
  "budget_limit_usd": null,          // overrides project/default budget
  "seed": null,
  "new_storyboard": false,           // extension: ask Claude for a new storyboard instead of reusing the stored one

```
`BatchOut = {id, project_id, status, settings, estimate, storyboard?, error, cost_usd, created_at, started_at, finished_at, counts:{total, done, rendering, queued, failed, cancelled}, clip_counts:{total, ready, generating, failed, reused}, reopened_from?, previous_error?}` — `reopened_from` / `previous_error` (extension): while a finished batch is re-opened for a re-render, the status and terminal reason it had before. `cost_usd` includes the reservations of clip attempts in flight (§7).
- `PATCH /api/batches/{id}` `{budget_limit_usd ≥ 0}` (extension) → `BatchOut` with children: sets `estimate.budget_limit_usd` (and `within_budget`), which every later clip reservation and retry admission uses — e.g. to resume a `budget_exceeded` batch by retrying its stopped videos.

### 5.7 Videos
- `GET /api/projects/{id}/videos?favorite=true|false&batch_id=&include_cancelled=true|false` → `[VideoOut]` (`include_cancelled` extension, default `true`; `false` leaves out `cancelled` videos)
- `GET /api/videos/{id}` → `VideoOut` (+ `lyric_lines` effective for this video, + `available_clips:[ClipOut]` for swapping)
- `PATCH /api/videos/{id}` `{favorite?, title?}` → `VideoOut`
- `POST /api/videos/{id}/retry` → re-render same plan (failed/cancelled) → `VideoOut`
- `POST /api/videos/{id}/regenerate` `{new_clips?:bool}` → new plan variant (new seed), re-render → `VideoOut`
- `PUT /api/videos/{id}/edit` `VideoEdit` → saves overrides, increments `render_version`, re-renders → `VideoOut`
  - `VideoEdit = {start?, lyric_style?, text_style?, color_grade?, lyric_offsets?:{line_id:{start,end}}, shots?:[{index, clip_id, src_in?}]}`
  - Field semantics (the `/videos/[id]/edit` page relies on them; absent/`null` = keep the current value):
    - `start`: absolute song seconds of the video start (same as `VideoPlan.start`); the duration is unchanged.
    - `text_style`: replaces the video's text overrides (`VideoPlan.text_style`); `{}` clears them back to the lyric-style defaults.
    - `lyric_offsets`: per-line timing for this video only, in **absolute song seconds** (same unit as `LyricLine.start/end`, hence `start ≥ 0`, `end > start`). Merged into the video's saved overrides by line id; the editor sends only the lines it changed. `GET /api/videos/{id}` returns `lyric_lines` with the overrides applied.
    - `shots`: replaces `clip_id` of the listed shot indexes (merged; other shots keep theirs). Without `src_in` the server keeps the shot's in-point when the new clip is long enough, else clamps it.
    - The response is the updated `VideoOut` (status `queued`/`rendering`, incremented `render_version`, `plan` already reflecting the edit).
- `GET /api/videos/{id}/download` → 302 to signed URL with `download=1` (Content-Disposition attachment, filename `{artist}_{title}_{index:02d}.mp4` ASCII-safe + RFC5987 utf-8 name)
- `VideoOut = {id, project_id, batch_id, index, title, status, progress, error, favorite, url?, thumbnail_url?, duration?, quality?, plan, render_version, created_at, rendered_at}`

### 5.9 As implemented (integration step)

All coded errors are `{"detail": <ja>, "code": <code>}`. A `ServiceError` may carry extra response headers (`headers=`, e.g. `Retry-After` on a 429); CORS exposes `Content-Disposition, Content-Range, Accept-Ranges, Content-Length, Retry-After` to the browser.

- **System**: `GET /api/system/capabilities` requires the normal auth (`CurrentUser`; only `/api/health` is public). `providers` = `registry.provider_info()` (adds `default_model`), `presets/lyric_styles/color_grades` from `presets.*_infos()` (`WorldPresetInfo` also declares `color_grades` and `lyric_styles` — the ids `auto` rotates through), `fonts` = the two Noto CJK JP families, filtered by `fc-list` when available. `whisper` = `lyrics_align.whisper_available()`.
- **Analysis (§5.3)**: rerun → 409 `audio_missing` without a song; returns the current status unchanged while `running`. `PUT /segment` → 409 `audio_missing`, 422 `segment_out_of_range` when `end` > song length (+0.05 s tolerance; a hair over is clamped). The analysis task stores the result only if `project.audio_asset_id` is still the analysed asset, and sets the default segment to the `suggested_segments` entry closest to 15 s (else `0..min(15, duration)`).
- **Lyrics (§5.4)**: upload accepts `.txt/.lrc/.srt` (`.txt` → auto-detect), ≤ 1 MB (413), decoded with `decode_bytes_with_info` (its warnings are returned). `PUT /lyrics/lines`: word timings follow an edited line (rescaled from the words' span) and are dropped when the line text no longer matches them. `POST /auto-time`: 422 `lyrics_missing` without lines; `heuristic` uses the analysis only when `analysis_status == done`; `whisper` → 503 `whisper_unavailable` (detail = the availability reason), otherwise `auto_time` first, then `align_lines` (sync route → FastAPI threadpool). Export file name `{artist}_{title}.{lrc|srt}` (`Content-Disposition` attachment, UTF-8 `filename*`).
  - **Stable line ids** (review fix): `PUT /lyrics` and `POST /lyrics/upload` pass the parsed lines through `pipeline.carry_over_lyric_lines(old, new, reserved_ids=pipeline.lyric_ids_in_use(db, project_id))`, because per-video `lyric_offsets` are keyed by line id. Old and new lines are aligned on normalised text (NFKC, case-folded, whitespace removed) with `difflib.SequenceMatcher(autojunk=False)` over the line sequence (inserted/removed lines and repeated choruses do not shift the others); inside a changed block an order-preserving similarity alignment pairs edited lines with the lines they replace (ratio ≥ `LINE_MATCH_MIN_RATIO` = 0.6). A matched line keeps its id; when its text is identical and the new input is untimed (TXT) it also keeps `start/end/words/source/confidence` (timed LRC/SRT input wins). Other lines get fresh ids `lNNN` after the highest id among the old lines and the ids the project's videos still reference in `lyric_offsets` (also in the fallback render's `plan.previous.plan`), so a new line never inherits another line's overrides.
  - **Rights reset** (review fix): when the sung line texts change (`PUT /lyrics`, `POST /lyrics/upload`, `PUT /lyrics/lines`; timing-only changes do not count, nor do section-heading lines that older versions stored as lines and the parser now leaves out), a confirmed `lyrics_rights` item is un-confirmed (`pipeline.revoke_right`, which also clears `rights_confirmed_at`), and the response's `warnings` start with `pipeline.LYRICS_RIGHTS_RESET_MESSAGE` (`LyricsParseOut.warnings`; `LyricLinesOut.warnings`, extension). No warning when the item was not confirmed.
- **Generation (§5.6)**:
  - `GenerationSettings.lyric_style: "auto"` (extension, offered in the UI as 自動（動画ごとに変える）): the planner rotates the preset's recommended styles (`WorldPresetInfo.lyric_styles`), so the videos of one batch get different styles; each video's `plan.lyric_style` is a concrete id. The generate form keeps `auto` from the previous batch.
  - `color_grade` must be `auto` or a `presets.COLOR_GRADES` id (422 `color_grade_unknown`, same as the editor) — for estimate, batch creation and regenerate.
  - `GenerationSettings.allow_mirror` (extension, default `false`; offered in the UI as 左右反転を使う): stored in `batch.settings` and passed to `plan_batch` for the estimate, batch creation, `run_batch` and regenerate (which re-plans with the batch's settings, so old batches without the key never flip). Shots are flipped only when it is true (§6.4), because a flip turns text and signage in the footage into mirror writing.
  - When the request omits `preset` / `custom_world`, the project's `world_preset` / `custom_world` are used.
  - `POST /estimate` plans with the storyboard the batch would use: the project's stored Claude storyboard for the same world (`stored_storyboard`, see §7) when one exists, else the deterministic template (no paid Claude call) plus the expected Claude cost when a key is set (6k input tokens + 1.5k + 700 per scene output; `new_storyboard: true` always prices a new call). It uses the request's `seed` (else 0) — the generate page sends one random seed for both the estimate and the batch, so the confirmed figure describes the run. Clips other batches of the project are still generating count as cached. The plan warnings are prepended to `notes`.
  - **Budget fit** (no-repeat addition, `pipeline._budget_fit`): when a non-library estimate is over a budget limit, `preview_batch` plans the batch once more with the largest `max_new_clips` the budget pays for and adds the result as `estimate.budget_fit` (§6.5) when that plan is within budget; its `note` is appended to `notes`. Applying the cap (same seed) reproduces exactly that estimate.
  - The budget is resolved as settings → project → `DEFAULT_BUDGET_USD`.
  - `POST /batches` guard codes (all 422): `audio_missing`, `analysis_missing`, `rights_unconfirmed`, `provider_not_configured` (from `check_model`), `library_empty`, `budget_exceeded`, plus `provider_unknown_model`, `color_grade_unknown`. The `budget_exceeded` message is 「見積もり $X が予算上限 $Y を超えています。」 followed by the `budget_fit.note` + 「。」 when there is one, else 「本数・新規生成数・再利用設定を見直すか、予算上限を引き上げてください。」.
  - Batch creation fixes a random `seed` when none is given (stored in `settings`, together with the resolved `model`), so the stored estimate describes exactly the plan the batch runs.
  - If the queue is down: 503 `queue_unavailable` and the batch is stored as `failed`.
  - `POST /batches/{id}/cancel`: idempotent on a cancelled batch; 409 `batch_finished` on other terminal states. Semantics in §7 (rendering videos are cancelled too; cancelling the re-render of a re-opened finished batch restores its earlier status and the previous renders).
  - `GET /batches/{id}/zip` and `POST /videos/zip`: streamed, uncompressed (`ZIP_STORED`, data descriptors, UTF-8 names = download names, de-duplicated with `_2`…). 409 `no_videos` when nothing is done. The ZIP file name is `{artist}_{title}_videos.zip` (sanitised) for a batch and `videos.zip` for a selection.
  - `POST /batches/{id}/zip-link` / `POST /videos/zip-link` (§5.6) sign the ids of the **finished** videos (409 `no_videos` when there are none) with the same file name; `GET /media-zip/…` (§5.8) streams them. The UI downloads every ZIP this way (also in token mode), so the archive is never held in page memory; the old endpoints stay for API clients.
  - `POST /storyboard` uses Claude when a route is configured (`settings.llm_configured`: Anthropic direct or OpenRouter, §6.3) and books an LLM `CostRecord` (batch_id null, `provider` = the route, note 絵コンテのプレビュー（Claude） / （Claude・OpenRouter 経由）) when it costs anything. It does not check the budget (preview only); with a key it sends the same data as a batch storyboard (RIGHTS_AND_SECURITY §5). The owner id goes in as `end_user` (OpenRouter's pseudonymous `user`). The guards below apply to both routes. Review fixes:
    - When the project has lyric lines and `lyrics_rights` is not confirmed, Claude is not called (the lyrics would be sent): the template is used and `storyboard.warnings` starts with `generation.STORYBOARD_LYRICS_RIGHTS_WARNING`; nothing is booked.
    - Claude previews are limited per user by `security.SlidingWindowLimiter` (`CLAUDE_PREVIEW_LIMIT = 10` per `CLAUDE_PREVIEW_WINDOW_SEC = 600`, in process memory): the 11th → 429 `{detail (ja, with the wait), code: "rate_limited"}` with a `Retry-After` header (seconds). Template previews are not limited and do not count.
- **Videos (§5.7)**:
  - `GET /videos/{id}`: `lyric_lines` = all project lines with this video's overrides applied. `available_clips` = the project's ready clips.
  - List order: newest batch first, then `index`. `include_cancelled=false` leaves out `cancelled` videos (the gallery's default).
  - `retry`: only `failed`/`cancelled` (409 `video_not_retryable`). It keeps the plan and `render_version`. Clips of the plan that this batch failed or cancelled (provider outage, budget stop, cancel) are reset to `pending` and generated again by the render task, after the batch budget admission check (422 `budget_exceeded`; raise the budget with `PATCH /api/batches/{id}` first).
  - `edit` / `regenerate` / `retry` require the rights checklist (422 `rights_unconfirmed`); the tasks re-check it, so withdrawing consent also stops queued work.
  - `edit` / `regenerate`: 409 `video_busy` while queued/waiting/rendering. Both increment `render_version`. Re-rendering a video re-opens a finished batch (`rendering`, with `plan.reopened_from` / `plan.previous_error`); its status is then recomputed. The finished render stays the fallback (`plan.previous = {plan, render_version, quality}`): when the re-render is cancelled or fails, the video returns to `done` with the previous plan and MP4, and `error` says why (…前回の動画を表示しています。).
  - `VideoEdit` semantics:
    - `lyric_offsets` = absolute song seconds per line id, merged into `plan.lyric_offsets` (422 `lyric_line_unknown`).
    - `text_style` replaces the plan's overrides (`{}` clears them).
    - `color_grade` must be a `presets.COLOR_GRADES` id (422 `color_grade_unknown`).
    - `start` must lie within `0..song − duration` (422 `start_out_of_range`).
    - `shots[]` takes a ready clip of the same project (422 `shot_unknown`/`clip_unknown`/`clip_not_ready`). `src_in` is clamped into the clip, and `clip_key` becomes null.
  - `regenerate` keeps the video's own start (`start_strategy=custom`), lyric style, per-line lyric timing (`lyric_offsets`) and — once edited — text overrides and colour grade (also a fixed batch grade); only shots, in-points and the seed change. `{new_clips:false}` plans with `max_new_clips=0`, so it uses cached/ready footage only and spends nothing. Outside library mode it plans at the batch's recorded `plan.stats.clip_duration` (when it is a positive number; `_plan(..., clip_duration=)`), so the batch's ready clips stay cache hits even if the model's clip length (snapping, the OpenRouter listing) changed since. When the ready clips are fewer than the video's beat shots, the video is re-cut into fewer, longer shots without repeats (§6.4); with no matching ready clip at all the planner refuses with 422 `no_clips` (the UI then suggests 「新しい素材も生成する」). `{new_clips:true}` sets `fresh_clips`, creates `pending` Clip rows (generated by the render task) and is refused with 422 `budget_exceeded` when spend + **every pending clip of the batch** + the new clips would exceed the batch budget.
  - `download` → 302 to the signed URL with `download=1&filename={artist}_{title}_{NN}.mp4`. **NN = `index + 1`** (1-based, 2 digits; deviation from the literal `{index:02d}`, so the first video is `_01`). 409 `video_not_ready`.
  - Plan keys added by the pipeline: `lyric_offsets`, `edited`, `regenerated`, `substitutions` (count), shot `substituted_from`, `previous` (fallback render while re-rendering); BatchPlan `seed`, `reopened_from`, `previous_error`. The UI shows substitutions in the batch table, gallery, preview and editor.

### 5.8 Media
- `GET /media/{key:path}?exp=&sig=[&download=1&filename=]` (NOT under /api; no auth header needed — the HMAC signature is the capability). Local storage only; supports HTTP Range (video seeking). S3 backend returns presigned URLs instead.
- `exp` is rounded up to a window of `ttl/10` (≤ 5 min), so repeated responses carry identical URLs and the browser cache works while the UI polls (a URL stays valid for `ttl` … `ttl + window` seconds).
- `GET /media-zip/{filename}?owner=&videos=&exp=&sig=` (extension; NOT under /api, not in OpenAPI, no auth header) streams the ZIP a `…/zip-link` call signed. `videos` = base64url of the raw 16-byte ids in selection order (≈ 11 KB for 500 ids); `sig = HMAC-SHA256(SECRET_KEY, "zip-link" \n owner \n sorted ids \n exp \n filename)` (`security.sign_zip_url` / `verify_zip_signature`). Valid for `MEDIA_URL_TTL` seconds; a tampered or expired link → 403. When streaming, the videos are reloaded joined to `Project.owner_id == owner`: videos that no longer belong to that owner (or were deleted) are left out; 409 `no_videos` when no finished one is left. Same streaming writer as `GET /api/batches/{id}/zip` (`zip_response`), plus `Cache-Control: private, no-store`. Works with any storage backend.

### 6.1 `audio_analysis.analyze_audio(path: str) -> dict`
Decode with librosa (via soundfile/audioread; for formats librosa can't read, transcode to WAV with ffmpeg first). Analysis at sr=22050 mono is fine. Return **AudioAnalysis**:
```json
{
  "version": 1,
  "duration": 60.0, "sample_rate": 44100, "channels": 2, "codec": "pcm_s16le", "bit_rate": 1411200,
  "bpm": 120.0, "bpm_confidence": 0.0-1.0,
  "beats": [seconds...], "downbeats": [seconds...],
  "loudness": {"hop": 0.5, "rms_db": [..]},                  // one value per 0.5 s
  "waveform": {"points": 1200, "peaks": [0..1 ...]},         // fixed 1200 peak points over the whole track
  "sections": [{"start":0,"end":8,"label":"intro|verse|chorus|bridge|outro|break","energy":0..1,"is_chorus_candidate":false}],
  "chorus_candidates": [{"start":24,"end":40,"score":0..1}],
  "highlights": [{"start","end","energy"}],                  // loudest regions
  "quiet_parts": [{"start","end"}],
  "suggested_segments": [{"start","end","duration":15|30|60,"score":0..1,"reason":"string(ja)"}],  // best per duration that fits; start snapped to a downbeat
  "vocal_activity": {"hop": 0.1, "values": [0..1]},          // heuristic vocal-likeness for lyric timing
  "mood": {"energy":0..1, "tempo_class":"slow|mid|fast", "brightness":0..1, "mode_guess":"major|minor", "tags":["energetic",...]}
}
```
Sections come from novelty/self-similarity segmentation (e.g. `librosa.segment.agglomerative` on beat-synced chroma+MFCC) plus energy; chorus candidates = repeated + high-energy sections. Results are heuristics: the UI lets the user override the segment.
As implemented: decoding stops at `MAX_DECODE_SEC = media.MAX_AUDIO_SEC + 1` (librosa `duration=`, FFmpeg `-t`), so even a file that bypassed upload validation cannot decode for hours. The `mood` tags feed `storyboard.estimate_world` (§6.3). Known bias: beats come out ≈ 30 ms late on the demo song (tracker latency, not compensated).
On the demo song, expected: bpm within 115–125; a chorus candidate overlapping 24–40 or 48–60; quiet parts include ~0–8 and ~40–48.

### 6.2 Lyrics
`LyricLine = {"id": str, "text": str, "start": float|null, "end": float|null, "words": [{"text","start","end"}]|null, "source": "manual|lrc|srt|txt|heuristic|whisper", "confidence": float|null}`
Times are **absolute seconds in the song**. Text is preserved exactly (strip only trailing newline/CR and leading/trailing whitespace; keep internal spaces); empty lines are dropped from `lines` but blank-line structure is kept in `lyrics_text`.
- `lyrics_parse.detect_format(text) -> "txt"|"lrc"|"srt"`
- `lyrics_parse.parse_lyrics(text, fmt="auto") -> tuple[list[LyricLine], list[str] warnings]` — LRC: `[mm:ss.xx]`, multiple tags per line, metadata tags ignored, `[offset:]` applied, enhanced `<mm:ss.xx>` word tags → words; end = next line start (last: start+4 s). SRT: index/timecode/text blocks, multi-line text joined with a space (warn). TXT: start/end null.
- `lyrics_parse.decode_bytes(data: bytes) -> str` (utf-8-sig, then cp932/shift_jis)
- `lyrics_parse.to_lrc(lines) -> str`, `to_srt(lines) -> str`
- `lyrics_timing.auto_time(lines, analysis, start=None, end=None, overwrite_timed=False) -> tuple[list[LyricLine], list[str]]` — heuristic: find vocal-active regions from `analysis.vocal_activity` (+ energy) within [start,end] (default whole song), distribute untimed lines proportionally to text length (characters, spaces ignored), snap line starts to the nearest beat (≤0.25 s), min line duration 1.0 s, no overlaps, `source="heuristic"`, `confidence≈0.3`. Also fill `words` with per-character (JA) / per-word (Latin) times by even split (karaoke style needs them).
- `lyrics_align.whisper_available() -> tuple[bool, str|None]`; `lyrics_align.align_lines(audio_path, lines, language="ja", model_size=settings.WHISPER_MODEL, start=None, end=None) -> tuple[list[LyricLine], list[str]]` — faster-whisper with word timestamps; align recognized chars to user lines with sequence matching on normalized text (NFKC, kana-folded, punctuation/space removed); **never replace user text**; lines without a confident match keep heuristic timing and get a warning. Raises `WhisperUnavailable` when the model can't be loaded.
- As implemented (compatible additions; ids are `l001`, `l002`, … in time order for LRC/SRT, text order for TXT; parsed lines have `confidence: null`):
  - `decode_bytes` order: UTF-8-BOM → UTF-16-BOM → UTF-8 → CP932 (⊇ Shift_JIS) or EUC-JP, whichever reads as more plausible Japanese → UTF-8 with U+FFFD; data containing NUL raises `LyricsParseError`. `decode_bytes_with_info(data) -> DecodedText(text, encoding, warnings)` returns the warning for the replacement fallback (use it in the upload route).
  - LRC: lines whose starts are within `SAME_TIME_SEC = 0.05` s (bilingual / duet layouts) form a group: they get the warning 「同じ時刻の行が N 組あります（対訳・デュエットなど）。動画では上下に並べて表示します。」 and share their end (the next distinct start) instead of ending each other. `[mm:ss]`, `[mm:ss.x|xx|xxx]`, `[mm:ss:xx]`; only known metadata keys (`ti ar al au by length offset re ve la …`) are dropped, so TXT headings like `[Chorus: …]` are not; a positive `[offset:+ms]` makes lyrics earlier; empty timed lines end the previous line; the last line ends at start+4 s (or its last word end, capped by `[length:]`); lines without a time tag are kept untimed (warning). **Instrumental breaks** (review fix, replaces the old "held > 15 s" warning): a line without an end tag normally lasts until the next line starts, but when that is `LRC_BREAK_GAP_SEC` = 10 s or more away and at least `LRC_BREAK_MARGIN_SEC` = 5 s more than the line needs, it ends after its estimated sung time = `lyrics_timing.line_weight` (morae/syllables) × `LRC_SEC_PER_MORA` 0.3 s + `LRC_TAIL_SEC` 1 s, clamped to `LRC_SUNG_SEC` 2.5–8 s, and never before its last enhanced-LRC word end + 1 s; lines of one same-time group end together; explicit empty end tags are always kept; one warning gives the count and the estimated durations (demo LRC: the line at 36 s ends at 41.5 s instead of 48 s). SRT: `<i>/<b>/<font>`/`{\…}` formatting tags are removed (warning); text after a blank line inside a cue stays with that cue (warning); cues are sorted by time; optional hours/millis and `WEBVTT` headers accepted. **Section headings** (review fix): `is_heading_line(text)` = a line that is only a bracketed label (`[]`, `［］`, `【】`, `〖〗`, `<>`, `＜＞`, `〈〉`, `《》`, `≪≫`, `〔〕`; ≤ 30 chars inside) or, after NFKC, a known JA/EN section label with a trailing colon (`Verse 1:`, `Pre-Chorus:`, `Chorus x2:`, `サビ：`, `Aメロ:`, `2番:` …). Round brackets are not headings (`(Oh oh)` is a sung backing vocal). Headings are left out of the TXT lines and of untimed LRC lines; a timed LRC heading only ends the previous line (it is not an explicit end tag for the break rule). `lyrics_text` keeps them verbatim; one warning lists them (≤ 5 shown). So a heading gets no vocal time and is never burned in.
  - `to_lrc(lines, *, include_words=False, metadata=None)`: writes an empty `[mm:ss.xx]` end tag when a line ends before the next one starts (and after the last line) so ends survive a round trip; untimed lines are written without a tag; `include_words` writes enhanced `<mm:ss.xx>` word tags. `to_srt` skips untimed lines (a missing end becomes the next start, else start+4 s).
  - `auto_time`: vocal activity (fallback: `loudness.rms_db`) is smoothed and hysteresis-thresholded relative to the whole song; runs are cut at pauses ≥ 0.2 s into phrase units (gaps < 0.6 s count as breaths inside a region); a small DP assigns each run of untimed lines (between kept lines, inside `[start, end]`) to units — one line may span several units, several lines may share one (split at the weakest activity), spurious units may be skipped — comparing voiced duration with the expected duration from text length (spaces/punctuation ignored, kanji ≈ 1.5 morae, Latin words by syllables). Gaps < 0.5 s between consecutive lines are closed. Lines spread evenly for lack of vocal activity get `confidence 0.15` and a warning. With a window, `overwrite_timed` re-times only lines whose start lies inside it. Helpers: `text_units(text)`, `line_weight(text)`, `fill_words(text, start, end)` (word texts are exact substrings of the line, in order). Demo song: mean start error 0.036 s.
  - `align_lines(..., transcriber=None)`: `transcriber(audio_path, *, language, start, end, initial_prompt) -> [(word, start, end)]` in song seconds replaces faster-whisper (tests/other engines). Matching is a semi-global Needleman–Wunsch alignment (not greedy `difflib`, which mis-maps repeated choruses); substituted characters take the time of the recognized character they align with; missing ones are inter/extrapolated at the line's pace; a line needs ≥ 40 % exactly matched characters (`confidence` = that ratio). Unmatched lines keep their timing unless it collides with aligned neighbours or is missing, in which case they are re-spread in the gap (`source="heuristic"`, `confidence 0.1`). With a window only untimed lines and lines starting inside it are aligned. Call `auto_time` first so unmatched lines have heuristic timing. `whisper_available(model_size=None)` uses `local_files_only` (≈0.4 s, no network; failures cached 5 min; `reset_whisper_cache()`); `WHISPER_MODEL` may be a size/repo id in the local HF cache or a CTranslate2 model directory. Audio is decoded with FFmpeg (16 kHz mono) because `faster_whisper.decode_audio` is incompatible with the installed PyAV 19.

Rules: shot boundaries land on beats (beat shots: 1 or 2 bars from analysis BPM, clamped 1.5–6 s; vary per video). When a generated video's beat cuts outnumber the distinct pool clips, it is re-cut on beats into the fewest shots that need no repeated clip: shots up to 8 s (`MAX_FIT_SHOT_SEC`), played at 0.75× or faster (`FIT_MIN_SPEED`), as even as the beat grid allows (minimax on the slowest shot), preferring section and lyric-line starts and downbeats, with the renderer's crossfade frames reserved (0.34 s per inner shot, 0.23 s for the first and last); a crossfade video becomes a `cut` video when only that avoids a repeat (details below). Shots sum exactly to `duration`; `src_in + duration*speed ≤ clip duration` (a fitted shot: `src_in + (duration + pad)*speed`); start time per `start_strategy` (`segment` = user segment start, `chorus` = best chorus candidate, `varied` = rotate among suggested segments/chorus/verse starts snapped to downbeats, `custom` = start_sec), never beyond song end − duration (if song shorter than duration → duration = song length, warn).
Pool size K by `reuse`: `max_variety` → one clip per shot (capped 60), `balanced` → ≈ shots_total/3, `economy` → ≈ shots_total/6, at least min(shots_per_video, max(#scenes, `fit_clip_floor`)) (as implemented, below), at most `max_new_clips` new ones. Reuse ready clips whose `cache_key` matches (and, for `library`, all uploaded clips are the pool). Videos differ by start, shot order, in-points, flips, zoom/pan, color grade and (if `auto`) lyric style variant. `variety_score` = unique (clip, src_in bucket, flip) combos / shots_total; warn in Japanese when < 0.35 (e.g. 「素材の再利用率が高いため、動画間の映像バリエーションが限定的です」). (As implemented, flips are opt-in and the score counts framings — see below.)
`cache_key = sha256(provider|model|prompt|negative|duration|aspect|seed)`.

As implemented (additions):
- `make_cache_key(provider, model, prompt, negative, duration, aspect, seed)` formats `duration` as `%.3f` and `seed=None` as an empty string; `aspect` is `"9:16"`. The **model must be the resolved model id**: pass `settings["model"]` filled in (the planner otherwise asks `providers.registry` for the default, falling back to `"default"`).
- Clip seeds derive from (prompt, negative, take) — not from the batch seed — so a later batch with the same storyboard hits the cache. `settings["fresh_clips"]: true` (optional extension) mixes the batch seed in to force new footage (e.g. `regenerate {new_clips:true}`).
- Pool: K = `pool_target_size(reuse, shots_total, shots_per_video, n_scenes, fit_clips=0)` = clamp(max(⌈shots_total / divisor⌉, min(shots_per_video, max(1, n_scenes, fit_clips))), 1, min(60, shots_total)) (all policies capped at 60). `plan_batch` passes the **beat** (pre-fit) counts and `fit_clips = fit_clip_floor(duration_ms, clip_duration)` = ⌈D / L⌉ with L = clamp((clip_duration − 0.2)/0.9 − 0.34 s, 1.5 s, 8 s) (`NEAR_NATURAL_SPEED` = 0.9; 6 s clips → L ≈ 6.1 s): enough clips that an uncapped video can be fitted at about 0.9× without repeats. It only raises the pool when ⌈D / L⌉ exceeds #scenes and the reuse divisor gives fewer clips (long videos, few scenes; e.g. count 1, economy, 60 s, 8 scenes, 6 s clips: 8 → 10 clips; with 8 scenes and 6 s clips, videos up to ≈ 48 s are unaffected); `stats.pool_fit_floor` reports it (0 for library). The fit (below) runs after the pool exists, so for a given pool `new_clips`, cache keys and spend are exactly what they were without fitting. Takes are allocated to scenes in proportion to how much of the planned videos falls into the scene's section (plus its lyric line being on screen; weights from the beat cuts), with a floor so other scenes still appear; take ≥ 1 adds an "Alternate take …" hint. **Distinct scenes first**: when the paid slots (`min(pool_target, max_new_clips)`, or `pool_target` uncapped) are ≤ #scenes, a stable sort moves every *uncached* alternate take behind all first takes; cached takes keep their place, so `new_clips` can only go down. Cache hits inside K are free; further cache hits beyond K are added for variety at no cost (so `unique_clips` can exceed K). Every new (paid) clip is used by at least one shot; unused specs are dropped and keys renumbered `c01…`. `_variant_prompt` is memoised (`functools.lru_cache(maxsize=4096)`; `sanitize_prompt` is pure), which brings a count=1 plan from ≈ 200 ms to a few ms.
- `clip_specs[]` extra keys: `variant` (take index), `section`, `hints: {preset, palette, scene_type, camera_move, section}` (for the mock provider's `ClipRequest.scene`). Shots extra keys: `scene_id`, `section`. For cache hits the shot already carries `clip_id` (= `existing_clip_id`).
- BatchPlan extra top-level `warnings: [ja]` (song shorter than duration, start clamped, no chorus found, `max_new_clips` limiting the pool, fitted videos…, listed below); `stats` extra `pool_target` (pre-fit), `clip_duration`, `shots_per_video: [int]`, and the no-repeat fields below. Library mode: `clip_specs = []`, `stats.reused_clips = unique uploads used`, `new_clips = 0`.
- Shot lengths (beat cuts): "short"/"long" = 1/2 bars; when a bar is < 1.5 s the whole-bar counts that fit are used (e.g. 2/4 bars), when only one whole-bar length fits (slow songs) the other is a half-bar multiple. Whole-bar shots cut on downbeats whenever one is in range, else on the nearest beat; without beats the BPM grid is used. Clips needing slow motion below 0.6× are avoided; generated clips keep a 0.1 s margin at both ends.
- **No repeated clip inside a video** (no-repeat addition, constants exported in `variation.__all__`: `FIT_MIN_SPEED` 0.75, `NEAR_NATURAL_SPEED` 0.9, `MAX_FIT_SHOT_SEC` 8.0, `XFADE_PAD_SEC` 0.3 (= `render.CROSSFADE_SEC`, not imported), `FRAME_SLACK_SEC` 0.04, `REPEAT_GAP_SEC` 0.5, `SCENE_REPEAT_COST` 3.0, `SCENE_ADJACENT_COST` 3.0, `FIT_SLOW_WEIGHT` 10.0; private `_MAX_FIT_MS` 8000; plus `fit_clip_floor`). This replaces the old "never back-to-back" rule:
  - **Fresh-first** (hard pick rule, not a cost): a shot takes a clip not yet in this video whenever one is long enough (`duration ≥ (shot + pad) × 0.6`); the cost order (section/lyric match, batch-wide use, +`SCENE_REPEAT_COST` per earlier shot of the same storyboard scene in the video, +`SCENE_ADJACENT_COST` when the previous shot shows the same scene) only ranks among those. So in generated mode no clip appears twice in a video while the pool covers its shots.
  - **Fit to the pool** (generated mode only; `_fit_to_pool` / `_fit_cuts`): a video whose beat cuts outnumber `len(pool)` (free cache extras included) is re-cut. For k = len(pool), len(pool)+1, … (fewer than its beat cuts), with u = the shortest usable clip length in the pool (duration − 2 × edge margin): shot caps `min(8 s, u/0.75 − pad)`; a feasibility DP over the beat grid (same millisecond rounding as `_cut_points`, so cuts stay on beats; every shot 1.5 s – cap), a 20-step binary search for the smallest slowest-shot need (minimax, then 1 % slack), and a cost DP: squared deviation from the per-shot ideal length + `FIT_SLOW_WEIGHT` × squared slow motion + a boundary cost (0 at a section or lyric-line start within half a beat, 0.02 on a downbeat, 0.08 elsewhere). Ideal lengths are equal for count = 1 and weighted `Random(_stable_int("fit", seed, video, k)).uniform(0.9, 1.1)` per shot for count > 1; fitting draws nothing from the video RNG. The feasibility check and the minimax limits do not depend on the weights, so `_even_limits` (an `lru_cache` keyed by the relative beat grid, duration, caps, usable length and pads) computes them once for all the videos that share a start (and reuses them across plans with the same inputs, e.g. the estimate and then the batch creation); both DPs only visit the boundaries each shot can end on (from the start and back from the end), and the feasibility check finds a reachable start by bisection. A 50-video, 90 s capped batch plans in about 0.1–0.25 s.
  - **Videos that share a start** (`segment`, `chorus`, `custom`, and `varied` once its starts repeat): the 1 % minimax slack leaves little room for the weights, so fitted videos that share a start usually get the same, most even cuts. A video whose edit (clip, in-point, length and flip per shot) comes out identical to an earlier video's is planned again with a cost (+20 per earlier video) on the clip each earlier video with the same cuts used at that shot while the order so far still follows it, so it takes another clip order at no speed cost. Only when every clip order the retries find is taken (3 clips: 6 orders) is a fitted video re-cut on the next most even split (`_fit_cuts(avoid=…)`: the cheapest split within the ≥ 0.75× limits that is not one of the used-up splits at that start; same number of shots, so no repeat and no change in `shots_total`), e.g. at 72 BPM videos 7–10 of 10 from 3 clips at about 0.76× instead of 0.86×. When the beat grid allows no other split and every order is taken, the edit repeats (rare: e.g. 20 videos of 30 s from 3 clips at one start).
  - Fitted shots get no stylistic energy slow-down (speed 1.0 unless the footage requires less; planned at ≥ 0.75×).
  - **Crossfade padding**: a fitted crossfade video reserves the renderer's fade frames (`_shot_pads`: `XFADE_PAD_SEC + FRAME_SLACK_SEC` = 0.34 s per inner shot, `XFADE_PAD_SEC/2 + 2 × FRAME_SLACK_SEC` = 0.23 s for the first and last). It is fitted padded first, else unpadded with its transition switched to `cut` (better than a repeat). The video transition is drawn before the pool from the same `Random(_stable_int("video-look", seed, i))` value as before (the later draw was removed).
  - **Last resort**: only when even len(pool) shots of ≤ 8 s at ≥ 0.75× cannot fill the video (e.g. cap 2 for 20 s, cap 1 for 15 s), the smallest k > len(pool) that fits is used — the fewest extra shots, i.e. k − len(pool) repeats. A repeat is never adjacent (pool ≥ 2), takes the source window that overlaps the clip's earlier windows least (`REPEAT_GAP_SEC` = 0.5 s; disjoint when the clip has room; a last-resort fitted shot plays almost the whole clip, so in practice it shows the same footage again), and gets a punch-in framing (zoom base 1.12, delta ≤ 0.07) and a (pan, zoom direction) the clip has not had in this video. When no k fits the beat grid, the video keeps its beat cuts under the same pick rules. The plan never raises for this.
  - **Library mode**: uploads are not re-cut; fresh-first, the overlap-aware in-points and the punch-in apply, so long uploads give disjoint windows. Only an *overlapping* window (closer than 0.5 s; windows exactly 0.5 s apart are disjoint, with 1 µs for float noise) of the same upload counts as a repeat; 1–3 short uploads still plan.
  - **Packing in-points** (`_speed_and_in(taken=, room_after=)`): besides the 0.5 s grid, a clip shown earlier in the video also gets the spots right after and right before each earlier window (the gap apart). `room_after` (`_room_after`) is the footage this clip may still have to show later in the video: the later shots no unused clip is left for, spread over the pool (its longest ones, plus the gap each). After the least overlap, the in-point whose longest free stretch still holds `room_after` wins, then the least-used grid position, then the random draw. With nothing taken and nothing expected later, the choice and the RNG draws are as before. A single upload therefore keeps its windows disjoint whenever they fit side by side (a 12 s upload for an 8 s video no longer reports a repeat).
  - `_assign_unused` swaps a still-unused paid clip into a shot of an over-used clip; in a fitted video only when it plays that shot (plus its pad) at ≥ 0.75×. An unused clip is in no video, so the swap never creates a repeat.
- **Fit and repeat reporting**: each video gets `fit = {beat_shots, shots, fitted, min_speed, max_shot_sec, repeat_shots, overlap_repeat_shots, adjacent_repeat_shots, scene_repeat_shots}`, computed from the final shots and windows `(src_in, src_in + (duration + pad) × speed)`: `repeat_shots` = shots whose clip appeared earlier in the video (library: only an overlapping earlier window), `overlap_repeat_shots` = those whose window overlaps an earlier one, `adjacent_repeat_shots` = those right after a shot of the same clip (only a pool of one clip has them), `scene_repeat_shots` = another clip of a storyboard scene already shown (generated mode only). `max_shot_sec` is rounded to 0.1 s and `min_speed` to 0.01, as the notes print them (Python rounds a tie such as 5.25 to even, the UI's `toFixed` would round it up), so every surface shows the same figure. `stats` adds `beat_shots_per_video: [int]`, `fitted_videos`, `repeat_shots`, `overlap_repeat_shots`, `adjacent_repeat_shots`, `scene_repeat_shots`, `videos_with_repeats` (sums over the videos), `max_shot_sec`, `min_speed` (over all shots, rounded the same way), `repeat_warning` (ja | null) and `pool_fit_floor`; `shots_total` and `shots_per_video` describe the fitted plan, `pool_target` the pre-fit one.
- **Plan warnings** (ja, in `warnings`): `max_new_clips` = 0 → 「生成済みの素材{n}本だけで構成します」 (n = pool size); a cap > 0 below the pool target → 「新規生成の上限（{cap}本）により、素材数を{n}本に抑えました」 (as before); fitted videos without repeats, count = 1 → 「素材が{K}本のため、同じ映像を繰り返さないよう、ショットを{beat}→{n}にまとめました（最長{L}秒・最も遅いショット{v}倍速）」, count > 1 → 「素材が{K}本のため、同じ映像を繰り返さないよう、{m}本の動画でショットを長めにまとめました（…）」 (L with 1 decimal, v with 2; 「等速」 instead of the slowest speed when it is ≥ 0.995).
- **`stats.repeat_warning`** (not in `warnings`; `cost.estimate` adds it to `notes`): generated, count = 1 → 「素材が足りないため、動画内で同じ素材が{r}ショット再登場します（{how}で使います）。」, count > 1 → 「素材が足りないため、{v}本の動画で同じ素材が計{r}ショット再登場します（{how}で使います）。」. `{how}` names only what holds for every repeat: 「連続はせず、」 unless a repeat is adjacent (a pool of one clip), 「別の区間・」 unless a repeat overlaps an earlier window, then always 「寄りの構図」 — so the spec's 「連続はせず、別の区間・寄りの構図」 only when both hold; a last-resort fitted repeat plays almost the whole clip, so the usual text is 「（連続はせず、寄りの構図で使います）」, and cap 1 gives 「（寄りの構図で使います）」. Then the advice: cap > 0 → 「新規生成の上限を{N}本以上に引き上げると解消します」 (N = max(cap + 1, need − cached clips in the pool), need = ⌈D / min(8 s, (clip_duration − 0.2)/0.75 − 0.34 s)⌉); cap = 0 → 「生成済みの素材だけでは足りません。新しい素材を{need − pool}本以上追加すると解消します」 (at least 1); uncapped → 「動画を短くすると解消します」. Library → 「アップロード素材が足りないため、同じ映像が{r}ショット再登場します。素材を追加でアップロードすると解消します」.
- `lyric_style: "auto"` (part of GenerationSettings; the UI's 自動) rotates the preset's `lyric_styles`. Errors: `ServiceError` 422 with codes `analysis_missing`, `library_empty`, `storyboard_empty`, `no_clips` (`max_new_clips=0` and no cache hit).
- `start_strategy: "varied"` (review fix): candidates are chorus, verse and highlight starts plus `suggested_segments` whose duration is within ±25 % of the video length (bridge sections are not candidates). Windows with < 50 % sung coverage (the minimum of lyric-on-screen coverage and `vocal_activity` coverage — LRC holds over breaks overstate lyrics) or with more than 1.5 s of intro/bridge/break/outro in their first 3 s are dropped unless fewer than 2 remain; the rest are used best first by coverage + 0.5 × mean energy, and the user's own segment stays first. Demo song, 30 × 15 s: starts {24.03, 26.03, 18.04, 12.03, 8.03}.
- **Mirroring** (review fix): `hflip` is only ever true when `settings["allow_mirror"]` is true (`GenerationSettings.allow_mirror`, default false), because a flip turns text and signage in the footage into mirror writing. Footage (clip, in-point bucket) that comes back gets a camera move — (pan, zoom direction) — it has not had yet with the same mirroring (`_ken_burns(..., avoid=)`, a few redraws).
- **Variety score** (review fix): each footage (clip, in-point bucket) counts once, or twice when it returns framed differently (another camera move, or a mirror), divided by `shots_total`; further repeats add nothing. The formula is unchanged by the no-repeat work and is meant **across videos** (the UI labels it 「動画間の映像バリエーション」 and shows no bar for one video): a clip that returns in another in-point bucket or framing still scores as new, so it does not measure repeats inside a video — those are `repeat_shots` / `repeat_warning`.
- **Variety warning** (review fix): starts with `VARIETY_WARNING_JA` (「素材の再利用率が高いため、動画間の映像バリエーションが限定的です。」) and adds advice for each cause that applies: library mode with few uploads (upload more or make fewer videos), the `max_new_clips` cap below the pool target (raise it, with the suggested number), `reuse = economy` (choose 「バランス」 or 「バリエーション最大」, the UI's label for `max_variety`), the 60-clip pool limit (fewer videos or split the batch), ≤ 3 storyboard scenes (add scenes or redo the storyboard); otherwise a fallback that never recommends the setting already chosen. It is given the beat (pre-fit) shot total, so the pool-limit advice keeps its meaning.

### 6.5 `cost.py`
`PRICING: dict[provider_id, dict[model_id, ModelPricing]]` with `price_per_second_usd`, `clip_durations`, `default_duration`, `source_url`, `as_of`, `verified` (filled from docs/VIDEO_PROVIDERS.md research; mock/library = 0).
`estimate(settings: dict, plan_stats: dict, provider: str, model: str, *, cached_clips: int, llm_estimate_usd: float, budget_limit_usd: float|None) -> dict` **Estimate**:
```json
{"provider":"mock","model":"mock-v1","clip_duration":5,"videos":3,"shots_total":24,"unique_clips":8,"new_clips":8,"cached_clips":0,
 "price_per_second_usd":0.0,"video_generation_usd":0.0,"llm_usd":0.01,"total_usd":0.01,
 "naive_total_usd":0.01,"savings_usd":0.0,             // naive = every shot generated fresh (+ llm, like total_usd)
 "budget_limit_usd":50,"within_budget":true,"variety_score":0.8,"variety_warning":null,
 "comparison":[{"provider","model","total_usd","configured"}],   // same plan priced on every provider/model

 // additive, as implemented below (absent for older plans):
 "shots_per_video_min":8,"shots_per_video_max":8,"beat_shots_per_video_max":8,"fitted_videos":0,"max_shot_sec":4.0,"min_speed":0.9,

```
As implemented:
- `PRICING` is built from the providers' `ProviderModel`s (the single source of truth for prices): `ModelPricing{provider, model, name, price_per_second_usd, clip_durations, default_duration, max_clip_duration, source_url, as_of, verified, text_to_video, price_note}`. Helpers: `get_pricing(provider, model=None)` (default model when empty; unknown ids → `ServiceError` 422 `provider_unknown`/`provider_unknown_model`), `clip_cost_usd(provider, model, seconds)`, `TARGET_CLIP_SEC = 5.0`: the clip length the pipeline should request, i.e. `provider_clip_duration = provider.clip_duration_for(model, TARGET_CLIP_SEC)`, which equals `ProviderModel.default_duration`. The no-repeat work did not change `TARGET_CLIP_SEC`, the clip length (one `clip_duration` per batch; 6 s for `google/veo-3.1-lite`) or the cache key; only a free re-plan of an existing video pins the batch's recorded length (§5.9).
- Math: `video_generation_usd = new_clips × clip_duration × $/s`. `clip_duration` is `plan_stats.clip_duration`, else the model default; `library` → 0. Then `total_usd = video_generation_usd + llm_usd`, `naive_total_usd = shots_total × clip_duration × $/s + llm_usd` (one fresh clip per shot, no cache), and `savings_usd = max(0, naive_total_usd − total_usd)`. Money is rounded to 4 decimals. `shots_total` is the **fitted** count (§6.4), so a single video fitted to a pool of only new clips saves nothing (savings 0; the panel shows 「—」). Cached clips in its pool still count as savings (e.g. 4 shots from 1 new and 3 ready clips: naive 4 clips, total 1).
- Budget: `budget_limit_usd=None` falls back to `settings["budget_limit_usd"]`; if that is also `None` there is no cap and `within_budget` is true. The caller resolves settings → project → `DEFAULT_BUDGET_USD`.
- `comparison`: the selected model (its cache-aware total) plus every model that can generate from text (`text_to_video`), in registry order. Image-only `gen4_turbo` and `library` appear only when selected. Other models are priced as generating all `unique_clips` at their own `default_duration`, because cached clips are model-specific. `configured` = `provider.check_model(model)[0]`. Rows also carry `name, selected, clip_duration, price_per_second_usd, video_generation_usd, verified`. Known issue: once the project has cached clips, `unique_clips` includes free cache-only extras and ignores `max_new_clips`, so other rows can be over- or under-stated (no wrong spend: selecting a row re-estimates it exactly).
- Additive Estimate fields: `configured` (the selected model is usable now), `as_of`, `pricing_verified`, `pricing_source_url`.
- **Dynamic catalogues** (OpenRouter addition): a provider with `dynamic_catalogue = True` (`openrouter`) gets its models and prices from a cached API listing (§6.7). `PRICING` holds only an offline snapshot of it (`build_pricing` uses `provider.cached_models()`, never the network); `get_pricing(provider, model)` re-reads such a provider's `models()` on every call (cache / fetch / built-in list). `ModelPricing.price_known`; models without a known price are left out of `comparison` (and refused by `check_model`). The estimate note for OpenRouter says the price comes from the listing (or the research value) and that the real charge is booked from OpenRouter's `usage.cost` when the job finishes.
- `llm_usd` (pipeline `llm_estimate_usd`) is priced at the Anthropic list price of the configured route's model on both routes (`claude_cost_usd(llm.configured_model(), …)`); OpenRouter's reported `usage.cost` replaces it once the call is made.
- `notes` (ja): cost breakdown, cache reuse, savings vs. naive (amount and %), LLM share, variety warning, repeat warning, budget overrun, why the selected provider/model cannot start, and for API providers the "price as of … (unverified)" disclaimer.
  - Savings: 「素材を動画間で使い回すため、全 N ショットを新規生成する場合（$naive）より $X（P%）安くなります」 only for ≥ 2 videos without in-video repeats; otherwise 「素材を使い回すため、…」.
  - `stats.repeat_warning` (§6.4) follows the variety warning.
  - Budget overrun: 「予算上限 $X を $Y 超えています。新規生成数の上限を下げる（素材が少ない分はショットを長めにまとめます）、本数や動画の長さを減らす、または安いモデルを選んでください」 (it no longer suggests 「節約」).
- **Fit and repeat fields** (no-repeat addition, `cost._fit_fields`; each is written only when the plan stats have it, so estimates of older plans keep their shape; typed as optional `Estimate` fields in `schemas.py`): `shots_per_video_min` / `shots_per_video_max` (from `stats.shots_per_video`, fitted), `beat_shots_per_video_max`, `fitted_videos`, `max_shot_sec`, `min_speed` (both as rounded by the planner), `repeat_shots`, `overlap_repeat_shots`, `adjacent_repeat_shots`, `scene_repeat_shots`, `videos_with_repeats`, `repeat_warning`.
- **`budget_fit`** (added by `pipeline.preview_batch`, not by `estimate()`; `schemas.EstimateBudgetFit`, a `LooseModel`): when a non-library estimate is over a budget limit and `per_clip = video_generation_usd / new_clips > 0`, k = ⌊(limit − llm_usd + 1e-9) / per_clip⌋ (0 ≤ k < new_clips, and k = 0 only when the plan has cache hits). The batch is planned again with `max_new_clips = k` — same storyboard, existing clips and seed — and priced with the same `llm_usd` and limit; only when that estimate is within budget does the Estimate get
  `budget_fit = {max_new_clips: k, new_clips, total_usd, shots_per_video (max), beat_shots_per_video (max), max_shot_sec, min_speed, repeat_shots, note}` with
  `note` = 「新規生成の上限を{k}本にすると {total} で予算内に収まります（1本あたり{s}ショット・最長{L}秒・{最も遅いショット{v}倍速 | 等速}・{同じ素材の繰り返しなし | 動画内で同じ素材が{r}ショット再登場}）」, also appended to `notes`. It never hides repeats. The UI applies it as `max_new_clips = k` with the form's seed, which reproduces exactly that estimate; the budget is still not a planner input. The extra plan costs a few ms.

### 6.6 Rendering (`subtitles.py`, `render.py`, `quality.py`)
**TextStyle** (all optional overrides; defaults depend on lyric_style):
```json
{"font_family":"Noto Sans CJK JP","font_weight":"bold|regular|light","font_size":64,"primary_color":"#FFFFFF","highlight_color":"#4DA3FF",
 "outline_color":"#000000","outline_width":3,"shadow":1,"position":"bottom|center|top","bg_opacity":0.0,"letter_spacing":0,"max_chars_per_line":14}
```

Units (as implemented): `font_size` is the ASS `Fontsize` on the 1080×1920 canvas (Noto CJK glyphs are ≈0.69×font_size wide; scaled proportionally for other sizes); `letter_spacing`/`outline_width`/`shadow` are px on that canvas; `max_chars_per_line` counts full-width characters (half-width Latin ≈ 0.6) and is a soft limit — text never leaves the safe width (the line shrinks to ≥60 % instead); `font_weight` also accepts `thin|medium|semibold|black` (mapped to the fontconfig families `Noto Sans CJK JP Light/Medium/Black`, `Noto Serif CJK JP …`); colours `#RGB|#RRGGBB|#RRGGBBAA`. Invalid values fall back to the style default. In `karaoke`, `primary_color` is the not-yet-sung colour and `highlight_color` the sweep colour.
- `subtitles.build_ass(lines, *, style_id, text_style, segment_start, duration, width=1080, height=1920, beats=None) -> str` — times relative to the segment; lines clipped to [0,duration]; horizontal text only (no rotation tags); Japanese-aware line wrapping (prefer breaking at spaces/punctuation, never inside a word for Latin, max 2 lines); **Instagram Stories safe area**: no text above y=270 px or below y=1920−380 px (top 14%, bottom ~20%); `position` maps to top/center/bottom inside that area.
  Styles: `simple` (white bold sans, thin outline, soft shadow), `cinematic` (serif `Noto Serif CJK JP`, smaller, semi-transparent black box via BorderStyle=3, low position), `minimal` (light weight, small, letter-spacing, no outline, subtle shadow), `karaoke` (`\kf` per word/char from `words`, else even split; highlight_color sweep), `fade` (`\fad(in,out)` with in/out aligned to nearby beats when given, ~250–400 ms).
  Implementation notes: every visual line is its own `Dialogue` (`\an8\pos`), so line pitch and the block's extents (outline, shadow, box padding, fade rise) are computed exactly and kept inside the safe area; soft shadows are a blurred copy on layer 0; user text is escaped (`{`/`}` → `\{`/`\}`, a WORD JOINER after `\` so `\N`/`\h` stay literal, newlines → spaces). Default positions: `simple`/`cinematic`/`karaoke` bottom, `minimal`/`fade` center. Helpers: `safe_area(width, height)`, `wrap_text(...)`, `layout_text(...)`, `resolve_text_style(style_id, text_style)`, `escape_ass_text(text)`.
  Review fixes: lines starting within 0.05 s are one block (`_timed_lines` joins them with a newline, latest end, words of the first line only); `_layout_block` wraps each part separately with the smallest part's font size so the block stacks inside the safe area, and karaoke sweeps only the first part (the others stay static in the not-yet-sung colour). With `bg_opacity > 0` the box is a separate layer-0 event in style `LyricBox` (BorderStyle=3, always black at `bg_opacity`, invisible glyphs, padding covers outline + blur) under the layer-1 text event, whose `Lyric` style is BorderStyle=1 with the user's outline colour/width (no hard shadow in box mode). The editor/lyrics preview mirrors this (black box, outline kept, no shadow; same-start lines stacked).
- `render.render_video(spec: RenderSpec, progress_cb=None) -> RenderResult`
```python
@dataclass
class RenderShot: clip_path: str; src_in: float; duration: float; hflip: bool=False; zoom_from: float=1.0; zoom_to: float=1.06; pan: str="center"; speed: float=1.0
@dataclass
class RenderSpec:
    shots: list[RenderShot]; audio_path: str; audio_start: float; duration: float
    lyric_lines: list[dict]; lyric_style: str; text_style: dict; color_grade: str
    output_path: str; work_dir: str; beats: list[float] | None = None
    width: int = 1080; height: int = 1920; fps: int = 30
    crf: int = 18; preset: str = "veryfast"; audio_bitrate: str = "256k"   # preset: see measurements below
    audio_fade_in: float = 0.15; audio_fade_out: float = 0.8; transition: str = "cut"
@dataclass
class RenderResult: output_path: str; thumbnail_path: str; duration: float; size_bytes: int; log_tail: str
                    timings: dict[str, float] = {}   # prepare/encode/finalize/total seconds (added)
                    audio_gain_db: float = 0.0       # < 0 when a hot master was turned down (added, review fix)
```
  Each shot: trim → speed → scale-to-cover → animated crop (Ken Burns zoom/pan, cheap `crop` expressions; avoid `zoompan`) → optional hflip → fps 30, setsar 1; concat (cut) or `xfade` (crossfade 0.3 s, durations compensated so total = duration); color grade; subtle film grain/vignette per grade; burn ASS with `subtitles=...:fontsdir=` (libass; escape paths). Audio: single encode from the **original file** (`-ss audio_start -t duration`), `afade` in/out, AAC-LC, keep source sample rate if 44.1/48 kHz else 48 kHz, stereo. Output: H.264 High, yuv420p, 1080×1920, 30 fps CFR, `-movflags +faststart`, GOP 60. Thumbnail: JPEG 540×960 from ~1 s. `progress_cb(fraction, stage)` best-effort (parse `-progress pipe:1`).
  As implemented: thumbnail is written next to the output as `<output stem>_thumb.jpg`; the MP4 is written to a hidden `.<stem>.part.mp4` and renamed on success. Progress stages: `prepare` (0.0) → `encode` (0.03–0.95) → `thumbnail` → `done` (1.0); an exception raised by `progress_cb` kills FFmpeg and propagates (use it for cancellation). **Ken Burns at sub-pixel precision** (review fix; before, the per-frame `scale` + `crop` moved in whole pixels and juddered): each shot is cropped once in whole pixels to the box the camera move ever shows (`crop … exact=1`; a landscape source is no longer upscaled in full), scaled once to square pixels and at most the output size (`bicubic`), edge-padded (`pad` + `fillborders=mode=smear`, so interpolation never pulls in black), then resampled every frame by `perspective` (`eval=frame`, `interpolation=cubic`) with sub-pixel corner expressions of the frame number (`perspective` counts input frames from 1, accounted for) — the view is interpolated at the source's own density and one fixed `scale` takes it to 1080×1920, then `format=gbrp` (`render._ShotGeometry`). At fix time the measured motion jitter (residual std of the per-frame displacement) dropped from 0.27–0.60 px to ≤ 0.04 px; tracked dots stay within 0.25 px of the ideal curve (regression-tested; the old chain stepped 1–2 px). The source matrix is honoured (`in_color_matrix`, untagged HD → BT.709) and the output is tagged BT.709. Clips shorter than needed are slowed down to ≥60 % speed, else looped (`-stream_loop`). A crossfade plays each blended shot half a fade longer at each blended side; shots the planner fitted to a small pool (§6.4) already reserve that footage (0.34 s inner, 0.23 s first/last), so the renderer does not slow them further, loop them or reset their `src_in` (checked with `render._plan_shots` on 1448 fitted shots of simulated plans: none changed, slowest 0.751×; the renderer itself is unchanged); rotation (autorotate) and non-square SAR are honoured. Colour grades: `presets.COLOR_GRADES[id].ffmpeg_filter` when importable and valid (checked once with a tiny FFmpeg run), else `render.FALLBACK_COLOR_GRADES` (same ids, cheap `colorchannelmixer`+`curves`). Runs of expensive point filters (`colorbalance`, `colortemperature`, …) are baked into a 36³ `.cube` (Hald CLUT sampled through the same chain) and applied with `lut3d` (≈4× faster, mean error <1/255); vignettes become a cached mask frame + `blend=multiply`; grain is a soft half-resolution luma noise layer (`blend=grainmerge`), only for film-look grades. **True-peak headroom** (review fix): before encoding, the segment's true peak is measured (`ebur128=peak=true`) on exactly the audio chain that is encoded (same seek, fades and output format); only when it exceeds `TRUE_PEAK_CEILING_DBTP` = −1.0 dBTP is a pure linear `volume` gain appended to bring it to −1.0 dBTP (no limiter), otherwise the chain has no gain stage. `RenderResult.audio_gain_db` reports the gain (the pipeline does not store it). At fix time a 0 dBFS hard-clipped square went from +0.51 dBTP (15,852 decoded samples at or over full scale) to −0.35 dBTP after the AAC encode; the demo WAV's chorus at 24 s (−0.96 dBTP) gets −0.04 dB, the demo MP3 at 24 s none. Measured in the dev container (2 cores via `taskset`, 15 s 1080×1920, CRF 18), before the Ken Burns fix: veryfast ≈21–31 s per video (31 s with grain), faster ≈28 s, medium ≈34 s; SSIM vs. lossless is identical across presets (0.969), hence the `veryfast` default. With the `perspective` chain (2026-10-11, veryfast): `render_sample.py` 28.3 s (cut, `natural`), 36.8 s (crossfade, `teal_orange`), 36.7 s (cut, `vivid`); all shots from a 1080×1920 clip ≈ 35 s (fix-time measurement 19.5 s → 31.4 s, +61 %; mixed demo clips +15 %, 720×1280 +21 %, 1280×720 −21 %). Known: on a very smooth, low-detail landscape texture a slow pan comes out of x264 (CRF 18, veryfast) in small holds and jumps (residual jitter 0.23 px vs. 0.08 px at CRF 1); the filter graph's own output is smooth. The render writes `filtergraph.txt`, `lyrics.ass`, `ffmpeg.log` (and `grade_*.cube`) into `work_dir`. `scripts/render_sample.py` renders one 15 s sample per lyric style into `backend/var/samples/`.
- `quality.validate_output(path, *, expected_duration, width=1080, height=1920, fps=30) -> dict` **QualityReport** `{"passed": bool, "checks":[{"name","passed","value","expected"}], "loudness_lufs": float|null, "black_ratio": float}` — checks: container mp4, video h264 yuv420p, size, fps 30, duration ±0.1 s, audio aac present, audio duration matches, faststart (moov before mdat), black frames ratio < 0.5 (`blackdetect`), integrated loudness (`ebur128`, informational only).

**Dataclass additions.** Each has a default, so constructing with only the contract fields still works.
- `ProviderModel.default_duration`: the clip length for a 5 s request.

**Crash safety (review fix).** Hosted APIs (`ApiVideoProvider`):
- `generate(..., on_submitted=None)`: `on_submitted(job_id, resume_token)` is called right after the job was created (exceptions are swallowed). The pipeline persists `Clip.external_job_id` and `params.open_job = resume_token` at once. `mock` / `library` accept and ignore the keyword.

- Kling (new API): a task that the `external_task_ids` lookup does not list for `MAX_LOOKUP_MISSES = 6` polls in a row (≈ 1.5 min) fails with a non-retryable `ProviderTaskError` instead of waiting for the 900 s timeout; an unexpected lookup shape is a retryable `provider_bad_response` (bounded by the poll-error limit).

**`generate(...)` behaviour.**
- `on_progress(fraction, stage)` reports stages `submitted|queued|running|downloading|done`. It is best effort and its exceptions are swallowed.
- `cancel_check()` is checked before submit, between polls and during download.
- Errors:
  - Missing keys → `ProviderNotConfigured`.
  - Rejected before any job exists → `ProviderError(retryable)`. Retryable: 429, 5xx, 408, timeouts and connection errors. Not retryable: other 4xx.
  - Job-creating requests sent with `_submit_request(client, method, url, *, what, **kw)` (OpenRouter's `POST /videos`; it has no idempotency key) are stricter: only failures that prove no job exists are retryable — connect-phase transport errors (`ConnectError`, `ConnectTimeout`, `PoolTimeout`, `ProxyError`, `UnsupportedProtocol`) and `submit_retryable_statuses` = {408, 425, 429, 503, 529}. A read/write timeout, a dropped connection or any other 5xx (500, 502, 504, 524…) raises `ProviderSubmitAmbiguous` (`code="provider_submit_ambiguous"`, never retryable, class attribute `billed = True`); an adapter turns an unreadable 2xx (bad JSON, missing/unsafe id) into the same via `_submit_ambiguous(what, reason)`. Veo, Runway and Kling still submit through `_request` (known gap: an ambiguous submit there can be resent).
  - `ProviderTaskError.http_status`: the status of the failed HTTP response (downloads), when there was one.
  - Failures after submission → `ProviderTaskError(ProviderError)` with `external_job_id` and `failure_code`.
  - Cancel → `ProviderCancelled(ProviderTaskError)` with `code="provider_cancelled"`, not retryable.
  - Timeout → `ProviderTaskError(code="provider_timeout", retryable=True)`.
  - Runway tasks are DELETEd on cancel or timeout. Veo and Kling have no cancel API, so an abandoned job may still be billed.
- Up to 5 consecutive transient poll errors are tolerated.
- After a job **succeeded** it is billed and never submitted again: only download + probe are retried, up to `OUTPUT_FETCH_ATTEMPTS = 3` times on the poll backoff within the timeout, re-reading the job's output in between (`ApiVideoProvider._refresh_output`; the default re-polls — Runway hands out fresh pre-signed URLs). Every error raised after success is a `ProviderTaskError` with `retryable=False` and `cost_usd` = the reported cost or the table price (`ProviderTaskError.cost_usd: float | None`); a `ProviderCancelled` raised during the fetch also carries it. A succeeded job is never cancelled/DELETEd.
- Downloads:
  - Written atomically and capped at `MAX_VIDEO_MB`.
  - Credentials go only to the API origin, never to redirect targets.
  - `download_file(..., allow_url=)` (optional) vets every hop including redirects (SSRF guard; a refused URL is a non-retryable `provider_bad_output`). `ApiVideoProvider._download_output(dl, job, outcome, out_path, *, cancel_check)` is the one-try download hook (OpenRouter: `/content`, then `unsigned_urls`).
  - The file is probed with ffprobe.
- `ClipResult` contents:
  - `width/height/duration` are the probed values.
  - `cost_usd` is Runway's `cost.credits × $0.01` when reported, otherwise price × requested (snapped) duration.
  - `raw` holds `requested_duration` and the submit/final status, never secrets.

Details and the [A]/[B]/[C] provenance of each field: docs/VIDEO_PROVIDERS.md §8 (§8.10 = implementation notes).
- Configured with `OPENROUTER_API_KEY`. `dynamic_catalogue = True` (§6.5), `supports_remote_cancel = False` (no cancel endpoint), poll every 5 s → 30 s (×1.5, ±20 % jitter).
- **Catalogue**: `GET {base}/videos/models` only when a key is set, cached per API base in memory and in `WORK_DIR/cache/openrouter_video_models.json` (no key in it) for `OPENROUTER_MODELS_CACHE_TTL`. A failed fetch — or a 200 listing with no usable model — keeps the previous listing (memory or file, marked stale) or else the built-in list (`FALLBACK_MODELS` / `STATIC_PRICES`), does not overwrite the file, and is retried only after 300 s. Without a key the built-in list is used and the file cache re-checked every 60 s. `info()` adds `models_source`, `models_fetched_at`, `models_note`.
- **Model mapping** (`_models_from_entry`): ids must match `vendor/name` (≤ 90 chars, no `@`); upscalers and models whose `supported_aspect_ratios` lacks `9:16` are left out (counted in `models_note`); unknown aspect ratios → listed with `supports_vertical: false` and a note. Durations from `supported_durations` (else the built-in ones, else 5 s); resolution: 720p first (`_RESOLUTION_PREFERENCE`); an `<id>@1080p` variant only when 1080p has its own SKU price. Price per second from `pricing_skus` (`sku_price_per_second`: per-second SKUs for the resolution, else generic; silent-audio SKUs preferred; else the highest), else `STATIC_PRICES`, else `price_known: false`. Default model: `OPENROUTER_VIDEO_DEFAULT_MODEL` when listed with a price, else the cheapest priced text-to-video model.
- **Submit** (`POST {base}/videos` via `_submit_request`): `{model, prompt (+ " Avoid: <negative>." — no negative field), duration (int), aspect_ratio "9:16", resolution?, generate_audio: false (only when the model generates audio), seed? (only when the listing says `seed: true`, modulo 2³¹), frame_images? (first frame as a data URI, ≤ 10 MB)}`. Never sent: `provider` (the video schema has no `zdr` / `data_collection`; video is not ZDR-eligible), `size`, `callback_url`, `user`. Ambiguous failures → `ProviderSubmitAmbiguous` (above). 402 → `provider_payment_required` (credits), 401 → `provider_auth_failed`, 403 → `provider_rejected`, 413 → `provider_bad_input`; none retryable.
- **Poll** `GET {base}/videos/{id}` (`polling_url` only when it has the API's origin): `pending`/`in_progress` wait; `completed` → download; `failed` → `ProviderTaskError` (`provider_content_filtered` when the error names moderation/safety, else `provider_failed`, retryable only for transient wording), `cancelled` → `provider_failed`, `expired` → `provider_bad_output` (presumed billed); `usage.cost` is carried as `cost_usd` and kept on the job.
- **Download**: `GET {base}/videos/{id}/content?index=0` with the key (`Accept: video/mp4`), then the `unsigned_urls` (≤ 3) without it. Every hop must be the API origin or https on a public host (`_is_public_host`: rejects localhost / `.local` and non-global IP literals, including the numeric forms `inet_aton` accepts such as `2130706433`, `0x7f000001`, `127.1`; DNS names resolving to private addresses are not caught). 409 → retryable `provider_not_ready` (within the timeout), 410 → `provider_bad_output`.
- **Cost**: `ClipResult.cost_usd` = the reported `usage.cost`, else price × seconds (`raw.cost_source` `usage.cost|estimate`, `raw.cost_note` ja → the clip's CostRecord note). BYOK (`is_byok: true`): never below price × seconds (usage.cost may be OpenRouter's fee only).
- **Resume**: `_prepare_resume` uses the listed model while it is listed with a price, else a minimal unverified model built from `req.model` (api model = the part before `@`), priced from `submitted_usd`, else `STATIC_PRICES`; no submission checks (price, aspect ratio, image). New submissions of such a model are still refused.

## 7. Pipeline & jobs (`pipeline.py`, `worker.py`)

Task functions (idempotent, take IDs, open their own DB session):
- `analyze_project_audio(project_id)` → runs `analyze_audio`, stores analysis, sets default segment (best 15 s suggestion) if none, `analysis_status=done|failed`.
- `run_batch(batch_id)` → status `planning`: storyboard (Claude or template; record LLM CostRecord) → `plan_batch` → create Clip rows (reuse by cache_key: CostRecord `cached=true`, amount 0) and Video rows (status `waiting_clips`, plan with `clip_key`s) → status `generating_clips`: generate missing clips (bounded concurrency, budget check before each paid clip → `budget_exceeded`, cancel check, retries with backoff for retryable errors up to 3 attempts) → resolve `clip_id`s into video plans → status `rendering`: enqueue `render_video` per video → batch status recomputed when each video finishes (`completed` all done; `partial` some failed; `failed` none done).
- `render_video(video_id)` → download inputs via storage to work dir, `render_video` → `validate_output` → upload MP4 + thumbnail → `status=done` (quality stored even if a check fails; failed hard checks → `status=failed` with error).
- `TASK_MODE=inline`: `worker.enqueue(name, *args)` submits to process-wide thread pools (one per task kind, see below); `celery`: `apply_async`. Same task bodies either way. Celery app name `mvf`, tasks `mvf.analyze`, `mvf.run_batch`, `mvf.render_video`. Run worker: `celery -A app.worker.celery_app worker -l info -c 2`.
- Cancellation: batch `cancelled` → pending/waiting videos → `cancelled`; running tasks check between steps.

As implemented (`app/pipeline.py`, `app/worker.py`; review fixes included):
- **Shared helpers** (used by the routers): `preview_batch(db, project, settings) -> BatchPreview{settings, storyboard, plan, estimate, budget_limit_usd}`, `create_batch(db, project, settings) -> Batch` (guards above), `cancel_batch`, `reopen_batch`, `prepare_retry`, `update_batch_budget`, `apply_video_edit(db, video, VideoEdit)`, `regenerate_video_plan(db, video, new_clips=)`, `recompute_batch_status(db, batch_id)`, `require_rights(project)`, `resolve_generation_settings`, `existing_clip_refs(db, project_id, include_in_flight=)`, `stored_storyboard`, `effective_lyric_lines(lines, overrides)`, `retime_line`, `carry_over_lyric_lines(old, new, reserved_ids=)` / `lyric_ids_in_use(db, project_id)` (stable line ids, §5.9), `revoke_right(project, key)` (+ `AUDIO_RIGHTS_RESET_MESSAGE`, `LYRICS_RIGHTS_RESET_MESSAGE`), `download_filename`, `generate_clip(clip_id, cancel_check=)`, `resolve_plan_clips(db, plan, project_id, preferred=, provider=, model=)`, `llm_cost_record`, `abandon_video`, `recover_interrupted_jobs(stale_after=None)`.
- **Rights**: `require_rights` (422 `rights_unconfirmed`) guards batch creation, regenerate, edit and retry; the tasks re-check it (`run_batch` fails the batch, `generate_clip` fails the clip without submitting, a render fails the video), so withdrawing consent stops queued work. Changing the content a confirmation vouched for withdraws it (`revoke_right`, review fix): a song upload un-confirms `audio_rights`, a change of the sung lyric text un-confirms `lyrics_rights` (§5.3, §5.9) — and with it `rights_confirmed_at`, so queued work stops the same way.
- **Planning** (`run_batch`, status `planning`):
  - The storyboard comes from Claude when a Claude route is configured (`ANTHROPIC_API_KEY` → Anthropic directly, else `OPENROUTER_API_KEY` → via OpenRouter; §6.3), else the template. Library mode has no storyboard. `build_storyboard` passes the project owner as `end_user`.
  - **Claude storyboard reuse**: storyboards carry `world_key` = sha256 of (preset, custom world, title, artist, mood, purpose, audio asset, lyric texts, and the artist aliases when set). `stored_storyboard()` returns the project's latest Claude storyboard with the same key; planning and `POST /estimate` reuse it (the estimate then has `llm_usd` 0, counts its cache hits and adds a note). `new_storyboard: true` asks for a fresh one. Without Claude the template is deterministic per song/preset anyway.
  - An LLM `CostRecord` is booked whenever `cost_usd > 0` (also when the batch was cancelled meanwhile), and that amount goes into `batch.cost_usd`. Its `provider` is the route the call took (`anthropic` or `openrouter` — the latter shares the provider id with the OpenRouter video provider, so the dashboard's `openrouter` row includes both), `model` the answering model, note 絵コンテ生成（Claude） / 絵コンテ生成（Claude・OpenRouter 経由） (`llm_cost_label`), plus ・テンプレートにフォールバック after an unusable answer.
  - `plan_batch` uses the settings seed and the project's ready clips **plus clips other running batches are still generating** (`include_in_flight`: a matching `cache_key` is a hit; the batch waits for that clip instead of paying for it twice). The clip cache is **per project**.
  - Clip rows are created **at planning time**: `pending`, `source = provider id`, `params = {batch_id, key, seed, duration, variant, section, hints, aspect_ratio}`. Shot `clip_id`s are resolved immediately and stored in `plan.clip_specs[].clip_id`. Cache hits get a `CostRecord(cached=true, amount 0, units = clip seconds, unit_price = model price)`. Videos are created as `waiting_clips`.
  - Rows, `batch.plan`, storyboard, settings and cost are committed in one transaction **only while the batch is still `planning` and this task owns it** (conditional UPDATE on `status` and the `started_at` token); a batch cancelled during a long Claude call gets no rows.
- **Budget** (no per-task in-memory guard): before **every** clip attempt its estimated price is reserved atomically in the database — `UPDATE batches SET cost_usd = cost_usd + :est WHERE id = :id AND cost_usd + :est <= :limit` (`_reserve_budget`); rowcount 0 = refused. So `batch.cost_usd` includes in-flight reservations and two renders/tasks can never both spend the same headroom. Each attempt settles its reservation to the real cost, to the billed cost of a failed attempt, or to 0. The admission checks of regenerate/retry (`_check_batch_budget`) count spend + every pending clip of the batch.
- **Generation** (`generating_clips`):
  - Before generating, the whole plan is priced; if spend + new clips would exceed `estimate.budget_limit_usd`, the batch goes to `budget_exceeded` and nothing is generated.
  - Clips are generated by `CLIP_CONCURRENCY = 2` threads. Each clip is **claimed** first (`pending → generating` with a conditional UPDATE): two tasks never generate the same row; a clip another task owns is waited for (`_wait_for_clips`, cancellable; a `generating` clip without heartbeat for `STALE_CLIP_SEC` = 600 s, or a `pending` one whose batch no longer runs, is not waited on). Generating clips heartbeat `updated_at` every `CLIP_HEARTBEAT_SEC` = 30 s through the cancel check.
  - A budget refusal cancels that clip (`params.budget_refused`) and the clips not started yet; after the in-flight ones finish the batch becomes `budget_exceeded`: pending clips and waiting videos are `cancelled`.
  - Retries: up to `MAX_CLIP_ATTEMPTS = 3` for retryable `ProviderError`s, with backoff `RETRY_BACKOFF_SEC = (5, 20)` (cancellable) — **unless the failed attempt is known or presumed billed**, which fails the clip instead of paying twice.
  - **Billed failures** (`_billed_usd`): a provider-reported `exc.cost_usd` is authoritative, even 0 (Runway credits of a FAILED task; the price of a succeeded job whose video could not be fetched); `exc.billed` → the estimate (e.g. `ProviderSubmitAmbiguous` / `provider_submit_ambiguous`: a submit whose outcome is unknown is never resent; the clip fails with 「…重複課金を避けて再送信しませんでした（推定額を課金済みとして計上します）」). A remote job that *ended with an error* (`provider_failed`, `provider_content_filtered`) is presumed not billed and may be retried. Presumed billed at the table price: unusable output of a finished job (`provider_bad_output`) and a job **abandoned** while it may still run (timeout, lost polling, cancel) on a provider without remote cancel (Veo, Kling); Runway's abandoned tasks are DELETEd. Every billed attempt gets a `CostRecord` (note 課金済み・生成失敗, plus （推定） when presumed) and its amount in `clip.cost_usd` / `batch.cost_usd`. A paid result that cannot be stored (storage error) is booked too.
  - **Job ids**: providers report the job right after submission (`on_submitted`); the clip keeps `external_job_id`, `params.open_job` and `params.submitted_usd` (the attempt's estimate). A clip with an open job and a provider with `resume()` resumes polling that job instead of submitting again (once). The resumed attempt is priced with `submitted_usd` (passed as `resume(..., submitted_usd=)` when the provider accepts it), and a `get_pricing` failure (model no longer in a dynamic catalogue) does not stop it. When a resumed attempt fails before the job can be followed (credentials removed, corrupt token, unexpected error), the estimate is booked as presumed billed (`_billed_usd(..., resumed=True)`; the error ends with `RESUME_FAILED_NOTE`). `submitted_usd` is dropped together with `open_job`.
  - A successful clip's `CostRecord.note` is the provider's `ClipResult.raw["cost_note"]` when given (OpenRouter: whether the amount is the reported `usage.cost` or an estimate).
  - `ProviderCancelled` → clip `cancelled`. `ProviderNotConfigured`, non-retryable errors and unexpected errors → `failed`, with a Japanese `error`. `ProviderTaskError` keeps `external_job_id` / `failure_code`.
  - A successful clip is stored as `Asset(kind=clip)` + `Asset(kind=thumbnail)` with a `CostRecord(video_generation, units = raw.requested_duration)`.
  - `cancel_check` = `CancelWatcher` (throttled DB read, every ≤ 1 s); for `run_batch` any batch status other than `generating_clips` counts as cancelled.
- **Start rendering**: the batch moves to `rendering` first (so two `run_batch` tasks cannot split the videos). Shots whose clip is not ready (failed, cancelled or deleted) are **substituted** by `resolve_plan_clips`: only clips of the same footage family (same provider and model; never mock clips in an API batch; uploads only in a library batch), the batch's own pool first, then the project's; ranked by own pool, avoiding the neighbouring shot's clip, avoiding a clip already in this video (no-repeat addition), same storyboard scene, least used — so a substitution can still repeat a clip when no unused ready clip exists. `src_in` is clamped; `plan.substitutions` counts them and shots keep `substituted_from`. A video with no acceptable clip at all → `failed` with a clear error. When a clip of the video's own batch was refused for budget, the video fails with the budget message instead of being substituted. Waiting videos → `queued`, then one `render_video` is enqueued per video (an enqueue failure fails that video and recomputes the batch).
- **Render**:
  - Pending clips of the plan are generated first (this is how regenerate/retry create clips); missing clips are substituted.
  - The video is **claimed** with a compare-and-swap (`queued`/`waiting_clips` → `rendering`, `attempts + 1`); a duplicate or stale task that loses the claim exits without side effects, and every later transition (progress, cancel, fail, done) is conditioned on the claimed `attempts`. Inputs are read via `storage.local_path` (local backend) or `fetch_to` into `WORK_DIR/renders/<id>-*`.
  - `render.render_video` gets the effective lyric lines, `analysis.beats` and the plan's style, grade and transition. Its `progress_cb` writes `progress` (0.02–0.95, ≤ 1/s) and raises when the batch or video was cancelled; FFmpeg is then killed.
  - Then `quality.validate_output`. A failed report → video `failed` with the failed checks listed in `error`, and the report kept in `video.quality`.
  - Otherwise the MP4 and thumbnail are uploaded as `Asset(kind=render)` (filename = download name) + `Asset(kind=thumbnail)`, and the video → `done` (`plan.previous` dropped). Assets of the previous render are deleted.
  - A cancelled or failed **re-render** of a finished video (`plan.previous` present and its MP4 still stored) returns to `done` with the previous plan, `render_version` and quality; `error` explains (`_end_video`).
  - The work directory is always removed, and the batch status is recomputed.
- **Cancel** (`cancel_batch` → `_stop_batch`): queued/waiting **and rendering** videos → `cancelled` (a running render notices at its next progress check and its `done` transition fails); every `pending` clip with `params.batch_id` = the batch → `cancelled` (also clips regenerate/retry created outside `plan.clip_specs`). Cancelling a batch re-opened for a re-render (`plan.reopened_from` = completed/partial/failed) restores the previous renders and recomputes its status; a re-opened `budget_exceeded` batch gets that status and reason back.
- **Concurrency safety**: status changes use conditional `UPDATE … WHERE status IN (…)`, so a cancel is never overwritten. `recompute_batch_status` locks the batch row (`SELECT … FOR UPDATE`). It acts only on `rendering|completed|partial|failed` batches; `cancelled` and `budget_exceeded` are final until a video is re-rendered. `partial` = some done, others failed **or cancelled** (the UI says 一部キャンセル when none failed).
- **Recovery**: `recover_interrupted_jobs(stale_after=None)`.
  - Inline mode (API start-up, `stale_after=None`): re-enqueues `queued`/`running` analyses, upstream batches (`run_batch` resumes: a stored plan skips planning) and queued/waiting/rendering videos of `rendering` batches (rendering ones are reset to `queued` first). Deletes task scratch directories (`WORK_DIR/{analysis,clips,renders,whisper}/*`) older than `STALE_WORK_SEC` (2 h). Inline mode is therefore single-process.
  - Celery (`worker_ready` signal, `stale_after = STALE_TASK_SEC` = 600 s): only work idle longer than that (upstream batches judged by their clips' heartbeats; videos by `updated_at`) is picked up, because other workers may be running. Redis would re-deliver an unacknowledged task only after the 6 h visibility timeout, so a crashed worker's work resumes when a worker (re)starts. Duplicate deliveries are harmless (clip and render claims).
  - Both settle terminal batches that still have active videos or pending clips, and reset `generating` clips whose task died to `pending`: the reservation is released; a job that can be resumed keeps `params.open_job`; an attempt that may have reached a provider that neither reports submissions nor resumes is booked as presumed billed (CostRecord 中断された生成ジョブ（課金済みとみなす）).
- **Inline pools** (`worker.INLINE_POOLS`): one `ThreadPoolExecutor` per task kind — `run_batch` 2, `render_video` 2, `analyze` 1 (others share a pool of 2) — so clip generation that waits minutes on provider APIs never starves analyses and renders.
- **Celery** (`worker.py`):
  - `celery_app = Celery("mvf", broker=REDIS_URL)` with `task_acks_late`, `task_reject_on_worker_lost`, `worker_prefetch_multiplier=1`, JSON only, `task_ignore_result`, queues `mvf` (default) and `mvf_batch` (`mvf.run_batch` is routed there), Redis `visibility_timeout` 6 h, a short publish retry policy and `imports=("app.pipeline",)`. A worker started without `-Q` consumes both queues; a dedicated `-Q mvf_batch` worker is optional.
  - Tasks `mvf.analyze` / `mvf.run_batch` / `mvf.render_video` call the registered bodies (`worker.CELERY_TASK_NAMES`).
  - `worker_process_init` disposes the inherited DB pool; `worker_ready` runs the recovery sweep above.
  - `DISPATCHERS["celery"]` publishes with `apply_async`. Names without a Celery task fall back to inline with a warning. A broker error raises `worker.QueueUnavailable` (`ServiceError`, 503 `queue_unavailable`). Routes turn it into a failed analysis, batch or video (re-renders fall back to the previous render) plus a 503, and the re-opened batch is recomputed; the audio upload still returns 201, with `analysis_status = failed`.
